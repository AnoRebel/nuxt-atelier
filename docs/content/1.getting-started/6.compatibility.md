## Supported versions

| | Supported |
|---|---|
| Nuxt | 4.6 and later 4.x releases, and Nuxt 5 (including its Nitro v3 server) |
| Node.js | 22, 24 and 26 |
| Other runtimes | Bun and Deno servers, and serverless platforms: see [deployment](/deployment/overview) |

One build of Nuxt Atelier runs on both Nuxt 4 and Nuxt 5.

## Older Nuxt versions

The module declares its supported range, so Nuxt checks it at startup. On Nuxt 4.5 or older you get:

```txt
Module `nuxt-atelier` is disabled due to incompatibility issues:
 - [nuxt] Nuxt version `>=4.6.0` is required but currently using `4.5.2`
```

By default Nuxt then skips the module and carries on. Set `experimental.enforceModuleCompatibility: true` in `nuxt.config.ts` to make it a build error instead.

## How compatibility is kept

- **Public APIs only.** Nuxt Atelier uses only documented Nuxt, Nitro and Vite APIs. It doesn't read private Nuxt options, import Nuxt internals or rewrite generated files, and a lint rule enforces this. That keeps it working across Nuxt releases.
- **Compiled packages.** Packages ship compiled JavaScript and type declarations, so they load on Nuxt 5 without a TypeScript loader.

## Versioning

Nuxt Atelier follows semantic versioning. Before 1.0, minor releases may include breaking changes, and each one is listed in the changelog with migration steps.
