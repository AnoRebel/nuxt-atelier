## Upgrading Nuxt Atelier

1. **Read the changelog** of the release you're moving to. Each package's `CHANGELOG.md` lists its changes; a breaking change links to its section on this page.
2. **Upgrade the packages together.** `nuxt-atelier`, `@nuxt-atelier/admin` and the other `@nuxt-atelier/*` packages you use are released together and expect the same version:

   ```bash
   npm install nuxt-atelier@next @nuxt-atelier/admin@next
   ```

   Until 1.0, releases are published under the `next` tag.

3. **Check for new migrations.** A release that changes Nuxt Atelier's own tables ships migrations for them. Run `atelier migrate status` to see what's pending, and `atelier migrate apply` (or deploy, with `migrations.autoApply`) to apply them. See [migrations](/reference/migrations).
4. **Run your tests and build**, then deploy.

Before 1.0, a minor release (0.3 → 0.4) may include breaking changes; patch releases never do.

## Breaking changes

Each release with breaking changes has a section here, newest first, saying what changed, who it affects and what to do. Changesets marking a change as breaking must link here (the repository's `scripts/check-changesets.ts` checks it).

There are none yet: 0.1 is the first release.

## Nuxt 5

Nuxt Atelier runs on Nuxt 4.6 and later and on Nuxt 5 from the same build (see [compatibility](/getting-started/compatibility)). To try your app with Nuxt 5 behaviour before upgrading Nuxt itself, opt in on Nuxt 4:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  future: { compatibilityVersion: 5 },
})
```

What that means for the parts of your app that touch Nuxt Atelier:

- **Nothing to change in your content code.** Definitions, blocks, roles, migrations and the admin work the same on both. Nuxt Atelier's server code is written against `nuxt/server`, which runs on Nitro 2 (Nuxt 4) and Nitro 3 (Nuxt 5).
- **Your own server routes** that call Nuxt Atelier (`useAtelierEntries`, `queryEntries`, …) work unchanged; follow Nuxt's own upgrade guide for anything else in them.
- **Localization:** use @nuxtjs/i18n under Nuxt 5 behaviour until nuxt-i18n-micro builds there (see [localization](/reference/localization)).
- **Packages are compiled**, so Nuxt 5 loads them without a TypeScript loader.
