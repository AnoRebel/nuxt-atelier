## Build-time options

Options go under the `atelier` key in `nuxt.config.ts`, with full type hints in your editor:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-atelier'],
  atelier: {
    admin: { base: '/cms' },
    limits: { maxUploadSize: 100 * 1024 * 1024 },
  },
})
```

Every option has a default, and the [configuration reference](/reference/configuration) lists them all. Options are checked when the build starts. An invalid value stops the build with a message naming the option, the value and what's accepted:

```txt
[nuxt-atelier] Invalid module options:
  - atelier.database.url = "mongodb://localhost/cms": unsupported scheme; accepted: file:, libsql:, postgres:, postgresql:, mysql:, mariadb:
```

A misspelled option fails the same way, listing the options that exist.

## Runtime settings

Secrets and anything that differs between environments are read from environment variables when the server starts, so you don't rebuild to change them:

| Variable | Sets |
|---|---|
| `NUXT_ATELIER_DATABASE_URL` | the database |
| `NUXT_ATELIER_STORAGE_DIR` | the upload directory |
| `NUXT_PUBLIC_ATELIER_SITE_URL` | the public site URL |
| `NUXT_APP_SECRET` | the session secret |

These are standard Nuxt [runtime config](https://nuxt.com/docs/guide/going-further/runtime-config) overrides.
