Nuxt Atelier runs wherever Nuxt's server runs (Node, Bun, Deno, and serverless platforms) with a database and file storage.

## Hosting guides

Each guide has complete example files to copy into your app. They're the files the deploy tests build, kept in `examples/hosting/` in the repository.

| Platform | Server | Database | Uploads |
|---|---|---|---|
| [Node on a VPS](/deployment/vps) | Node, run by systemd, behind Caddy | SQLite | the server's disk |
| [Docker and Docker Compose](/deployment/docker) | Node in a container | PostgreSQL | a volume |
| [Dokploy and Coolify](/deployment/dokploy-coolify) | the Docker guide's container | PostgreSQL | a volume |
| [Fly.io](/deployment/fly) | Node in a container | SQLite on a volume | a volume |
| [Railway](/deployment/railway) | Node | PostgreSQL | a volume |
| [Render](/deployment/render) | Node | PostgreSQL | a disk |
| [Bun](/deployment/bun) | Bun in a container | SQLite | a volume |
| [Deno](/deployment/deno) | Deno in a container | SQLite | a volume |
| [Vercel](/deployment/vercel) | serverless functions | PostgreSQL or libSQL | Vercel Blob |
| [Netlify](/deployment/netlify) | serverless functions | PostgreSQL or libSQL | S3-compatible storage |
| [Cloudflare Workers](/deployment/cloudflare-workers) | Workers | D1 | R2 |

Each starts from an app with the module and the admin, `modules: ['nuxt-atelier', '@nuxt-atelier/admin']`, and covers the build command and Nitro preset, the configuration files, environment variables, the database, migrations on deploy, media storage, scheduled jobs, real-time support, and what doesn't work on that platform with what to use instead.

Platforms that keep a server running (a VPS, containers, Fly.io, Railway, Render) run everything: background jobs on Nitro's scheduler, and the admin's real-time connection. Serverless platforms (Vercel, Netlify, Workers) have no disk that lasts: the database is a server or D1, and uploads go to object storage.

## Before going live

Go through the [security checklist](/deployment/security), set up [backups](/deployment/backup), and point your platform's health checks at the [health endpoints](/deployment/operations).
