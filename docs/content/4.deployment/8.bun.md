---
title: Bun
description: Run Nuxt Atelier's server on Bun, in a container or on your own server.
---

Nitro builds a server for [Bun](https://bun.sh) with the `bun` preset. It runs everything a Node server does: SQLite, uploads on disk, background jobs and the admin's real-time connection.

## Build command and preset

Set the `bun` preset in `nuxt.config.ts` (or `NITRO_PRESET=bun` at build), build, and start the output with Bun:

```bash
bun run build
bun .output/server/index.mjs
```

The container below builds with Node and runs on Bun.

## Configuration files

<!-- file: bun/nuxt.config.ts -->
```ts [nuxt.config.ts]
// Bun: the server built for Bun's runtime (the bun preset), configured from the environment.
export default defineNuxtConfig({
  modules: ['nuxt-atelier', '@nuxt-atelier/admin'],
  compatibilityDate: '2026-10-01',
  nitro: { preset: 'bun' },
})
```

<!-- file: bun/Dockerfile -->
```dockerfile [Dockerfile]
# Nuxt Atelier on Bun, in a container. Build from your app's root: docker build -t my-site .
FROM oven/bun:1.4.4 AS bun

# Nuxt builds on Node; the server it builds runs on Bun
FROM node:26-slim AS build
COPY --from=bun /usr/local/bin/bun /usr/local/bin/bun
WORKDIR /app
COPY package.json bun.lock* ./
RUN bun install --frozen-lockfile
COPY . .
RUN bun run build

FROM oven/bun:1.4.4-slim
# SQLite and uploads live in /app/.data: mount a volume there so they outlive the container
ENV NODE_ENV=production HOST=0.0.0.0 PORT=3000 \
    NUXT_ATELIER_DATABASE_URL=file:/app/.data/atelier.sqlite \
    NUXT_ATELIER_STORAGE_DIR=/app/.data/uploads \
    NUXT_ATELIER_MIGRATIONS_AUTO_APPLY=true
WORKDIR /app
COPY --from=build --chown=bun:bun /app/.output .output
RUN mkdir -p /app/.data && chown bun:bun /app/.data
USER bun
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s \
  CMD ["bun", "-e", "fetch('http://127.0.0.1:3000/api/_atelier/health/ready').then(r => process.exit(r.ok ? 0 : 1), () => process.exit(1))"]
CMD ["bun", ".output/server/index.mjs"]
```

Use the [Docker guide's](/deployment/docker#configuration-files) `.dockerignore` with it. Then:

```bash
docker build -t my-site .
docker run -p 3000:3000 -v my-site-data:/app/.data -e NUXT_APP_SECRET=… -e NUXT_PUBLIC_ATELIER_SITE_URL=https://example.com my-site
```

On your own server, use the [VPS guide's](/deployment/vps) systemd unit with `ExecStart=/usr/local/bin/bun .output/server/index.mjs` (where `which bun` says Bun is).

## Environment variables

| Variable | Value |
|---|---|
| `NUXT_APP_SECRET` | at least 32 random characters (`openssl rand -hex 32`). The server won't start without it. |
| `NUXT_PUBLIC_ATELIER_SITE_URL` | the site's public URL |
| `NUXT_ATELIER_AUTH_SETUP_TOKEN` | optional: first-run setup asks for it, so nobody else can become the first administrator |
| `NUXT_ATELIER_AUTH_TRUST_PROXY` | `true` behind a reverse proxy that sets `X-Forwarded-For` |

The image sets the database, the upload directory and automatic migrations, in `/app/.data`.

## Database

SQLite, in `/app/.data/atelier.sqlite`: mount a volume at `/app/.data`. For PostgreSQL, install `pg`, rebuild, and set `NUXT_ATELIER_DATABASE_URL`, as in the [Docker guide](/deployment/docker).

## Migrations on deploy

The image sets `NUXT_ATELIER_MIGRATIONS_AUTO_APPLY=true`: the server applies pending migrations when it starts.

## Media storage

Uploads go to `/app/.data/uploads`, on the volume.

## Scheduled jobs

Background jobs run in the server process, on Nitro's scheduler, every minute by default. On `SIGTERM` or `SIGINT`, running jobs get 10 seconds to finish.

## Real-time

The Bun server serves the admin's WebSocket itself: edits, locks and comments are pushed to other editors at once.

## Limitations

| Limitation | Instead |
|---|---|
| SQLite and the uploads volume serve one server | PostgreSQL and [S3-compatible storage](/reference/media#s3-compatible-storage-and-cloudflare-r2) |
