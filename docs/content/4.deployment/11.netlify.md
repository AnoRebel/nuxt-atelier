title: Netlify
description: Deploy Nuxt Atelier on Netlify with a PostgreSQL or libSQL database, S3-compatible storage, and a scheduler for jobs.
---

[Netlify](https://www.netlify.com) runs your app's server as functions. A function keeps no files between requests, so the database is a server reached over the network and uploads go to S3-compatible storage.

## Build command and preset

Netlify runs `npm run build` (set in `netlify.toml`), and Nitro picks the `netlify` preset by itself. The site's public files go to `dist`, the server to Netlify's functions. Each push deploys.

## Configuration files

<!-- file: netlify/netlify.toml -->
```toml [netlify.toml]
# Nuxt Atelier on Netlify: the build, and where the netlify preset puts the site's public files
[build]
  command = "npm run build"
  publish = "dist"
```

<!-- file: netlify/nuxt.config.ts -->
```ts [nuxt.config.ts]
// Netlify: the netlify preset, picked when building on Netlify. A function has no lasting disk: the database is a
// PostgreSQL or libSQL server, and uploads go to S3-compatible storage (npm install pg @nuxt-atelier/storage-s3).
export default defineNuxtConfig({
  modules: ['nuxt-atelier', '@nuxt-atelier/admin', '@nuxt-atelier/storage-s3'],
  compatibilityDate: '2026-10-01',
  atelier: {
    storage: { driver: 's3' },
    migrations: { autoApply: true },
    jobs: { schedule: false }, // no scheduler on Netlify: an external one calls the trigger endpoint
    auth: { trustProxy: true }, // Netlify sets X-Forwarded-For
  },
})
```

Install the database driver and the storage driver in your app:

```bash
npm install pg @nuxt-atelier/storage-s3
```

## Environment variables

Set them in the site's environment variables:

<!-- file: netlify/.env.example -->
```bash [.env.example]
# The site's environment variables (Site configuration, Environment variables). `openssl rand -hex 32` makes a secret.
NUXT_APP_SECRET=
NUXT_PUBLIC_ATELIER_SITE_URL=https://example.com
NUXT_ATELIER_DATABASE_URL=postgres://user:password@host:5432/atelier
# The secret your scheduler sends to POST /api/_atelier/jobs/run
NUXT_ATELIER_JOBS_SECRET=
# First-run setup asks for this token until the first administrator exists
NUXT_ATELIER_AUTH_SETUP_TOKEN=
NUXT_ATELIER_S3_ENDPOINT=https://s3.eu-central-1.amazonaws.com
NUXT_ATELIER_S3_BUCKET=media
NUXT_ATELIER_S3_REGION=eu-central-1
NUXT_ATELIER_S3_ACCESS_KEY_ID=
NUXT_ATELIER_S3_SECRET_ACCESS_KEY=
```

| Variable | Value |
|---|---|
| `NUXT_APP_SECRET` | at least 32 random characters (`openssl rand -hex 32`) |
| `NUXT_PUBLIC_ATELIER_SITE_URL` | the site's public URL |
| `NUXT_ATELIER_DATABASE_URL` | the database's URL |
| `NUXT_ATELIER_JOBS_SECRET` | a random value your scheduler sends to the trigger endpoint |
| `NUXT_ATELIER_AUTH_SETUP_TOKEN` | optional: first-run setup asks for it, so nobody else can become the first administrator |
| `NUXT_ATELIER_S3_*` | the bucket: see [S3-compatible storage](/reference/media#s3-compatible-storage-and-cloudflare-r2) |

## Database

A database server: PostgreSQL (`postgres://…`, with `pg`), or libSQL and Turso (`libsql://…?authToken=…`, nothing to install). A SQLite file doesn't work: it would be lost with the function.

## Migrations on deploy

`migrations.autoApply` in `nuxt.config.ts`: a new deploy applies pending migrations when its server starts. To apply them as a step before deploying instead, run `npx atelier migrate apply` with the production `NUXT_ATELIER_DATABASE_URL` from CI, and remove `autoApply`.

## Media storage

[S3-compatible storage](/reference/media#s3-compatible-storage-and-cloudflare-r2): AWS S3, Cloudflare R2, or any other. The bucket can stay private: your app serves the files.

## Scheduled jobs

`jobs.schedule: false`: Nuxt Atelier adds no schedule on Netlify. Have a scheduler call the [trigger endpoint](/reference/jobs#the-trigger-endpoint) every minute or so:

```bash
curl -X POST https://example.com/api/_atelier/jobs/run -H "Authorization: Bearer $NUXT_ATELIER_JOBS_SECRET"
```

## Real-time

Netlify's functions don't hold WebSocket connections, so the admin polls every 20 seconds instead: other editors' edits, locks and comments appear, only later.

## Limitations

| Limitation | Instead |
|---|---|
| No lasting disk: a SQLite file and local uploads are lost | a PostgreSQL or libSQL server, and S3-compatible storage for uploads |
| No schedule: jobs don't run by themselves | a scheduler calling the trigger endpoint with `NUXT_ATELIER_JOBS_SECRET` |
| No WebSocket: the admin polls every 20 seconds | a platform with a server, like [Docker](/deployment/docker) or [Fly.io](/deployment/fly), for changes pushed at once |
