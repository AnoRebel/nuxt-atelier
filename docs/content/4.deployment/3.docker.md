---
title: Docker and Docker Compose
description: Run Nuxt Atelier in a container, alone with SQLite or with PostgreSQL in Docker Compose.
---

The image builds your app, then keeps only its output and runs it on Node. With Docker Compose, a PostgreSQL container runs next to it. The same files run on [Dokploy and Coolify](/deployment/dokploy-coolify), and the Dockerfile on [Fly.io](/deployment/fly).

## Build command and preset

The preset is Nuxt's default, the Node server. The Dockerfile builds it with `bun run build` (your `build` script, `nuxt build`). Build and start everything with:

```bash
cp .env.example .env   # then fill it in
docker compose up -d --build
```

Or the image alone, with SQLite on a volume:

```bash
docker build -t my-site .
docker run -p 3000:3000 -v my-site-data:/app/.data -e NUXT_APP_SECRET=… -e NUXT_PUBLIC_ATELIER_SITE_URL=https://example.com my-site
```

## Configuration files

The app's config needs nothing for Docker: everything comes from the environment. PostgreSQL needs its driver in your app (`npm install pg`).

<!-- file: docker/nuxt.config.ts -->
```ts [nuxt.config.ts]
// Docker and Docker Compose: Nuxt's default Node server, configured from the environment (compose.yml, .env).
// PostgreSQL needs its driver in your app: npm install pg
export default defineNuxtConfig({
  modules: ['nuxt-atelier', '@nuxt-atelier/admin'],
  compatibilityDate: '2026-10-01',
})
```

The Dockerfile installs with Bun, from your `bun.lock` when there is one. With another package manager, replace the install lines, for example with `COPY package.json package-lock.json ./` and `RUN npm ci`.

<!-- file: docker/Dockerfile -->
```dockerfile [Dockerfile]
# Nuxt Atelier in a container. Build from your app's root: docker build -t my-site .
# It installs with Bun, from bun.lock when there is one: with another package manager, swap the install line.
FROM oven/bun:1.4.4 AS bun

FROM node:24-slim AS build
COPY --from=bun /usr/local/bin/bun /usr/local/bin/bun
WORKDIR /app
COPY package.json bun.lock* ./
RUN bun install --frozen-lockfile
COPY . .
RUN bun run build

FROM node:24-slim
# SQLite and uploads live in /app/.data: mount a volume there so they outlive the container.
# NUXT_ATELIER_DATABASE_URL set at run time (compose.yml) points the server at PostgreSQL instead.
ENV NODE_ENV=production HOST=0.0.0.0 PORT=3000 \
    NUXT_ATELIER_DATABASE_URL=file:/app/.data/atelier.sqlite \
    NUXT_ATELIER_STORAGE_DIR=/app/.data/uploads \
    NUXT_ATELIER_MIGRATIONS_AUTO_APPLY=true
WORKDIR /app
COPY --from=build --chown=node:node /app/.output .output
RUN mkdir -p /app/.data && chown node:node /app/.data
USER node
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s \
  CMD ["node", "-e", "fetch('http://127.0.0.1:3000/api/_atelier/health/ready').then(r => process.exit(r.ok ? 0 : 1), () => process.exit(1))"]
CMD ["node", ".output/server/index.mjs"]
```

```text [.dockerignore]

.nuxt
.output
.data
.env
```

<!-- file: docker/compose.yml -->
```yaml [compose.yml]
# Nuxt Atelier with PostgreSQL. Copy .env.example to .env, fill it in, then: docker compose up -d --build
services:
  app:
    build: .
    restart: unless-stopped
    ports:
      - "3000:3000"
    environment:
      NUXT_ATELIER_DATABASE_URL: postgres://atelier:${POSTGRES_PASSWORD:?set POSTGRES_PASSWORD in .env}@db:5432/atelier
      NUXT_APP_SECRET: ${NUXT_APP_SECRET:?set NUXT_APP_SECRET in .env}
      NUXT_PUBLIC_ATELIER_SITE_URL: ${NUXT_PUBLIC_ATELIER_SITE_URL:?set NUXT_PUBLIC_ATELIER_SITE_URL in .env}
      NUXT_ATELIER_AUTH_SETUP_TOKEN: ${NUXT_ATELIER_AUTH_SETUP_TOKEN:-}
      NUXT_ATELIER_AUTH_TRUST_PROXY: ${NUXT_ATELIER_AUTH_TRUST_PROXY:-false}
    volumes:
      - uploads:/app/.data
    depends_on:
      db:
        condition: service_healthy
    # running jobs get 10 seconds to finish when the container stops
    stop_grace_period: 15s

  db:
    image: postgres:18-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: atelier
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?set POSTGRES_PASSWORD in .env}
      POSTGRES_DB: atelier
    volumes:
      - postgres:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U atelier -d atelier"]
      interval: 5s
      timeout: 5s
      retries: 10

volumes:
  uploads:
  postgres:
```

The image's health check asks `/api/_atelier/health/ready`, which answers `503` while the database is out of reach or has pending migrations.

## Environment variables

Compose reads them from `.env`, next to `compose.yml`, and refuses to start while a required one is empty:

<!-- file: docker/.env.example -->
```bash [.env.example]
# Copy to .env and fill in. `openssl rand -hex 32` makes each secret.
NUXT_APP_SECRET=
POSTGRES_PASSWORD=
NUXT_PUBLIC_ATELIER_SITE_URL=https://example.com
# First-run setup asks for this token until the first administrator exists
NUXT_ATELIER_AUTH_SETUP_TOKEN=
# true behind a reverse proxy that sets X-Forwarded-For (Dokploy, Coolify, Caddy, nginx, Traefik)
NUXT_ATELIER_AUTH_TRUST_PROXY=false
```

| Variable | Value |
|---|---|
| `NUXT_APP_SECRET` | at least 32 random characters (`openssl rand -hex 32`). The server won't start without it. |
| `POSTGRES_PASSWORD` | the database's password. Use letters and digits only (`openssl rand -hex 32`): it's part of a URL. |
| `NUXT_PUBLIC_ATELIER_SITE_URL` | the site's public URL |
| `NUXT_ATELIER_AUTH_SETUP_TOKEN` | optional: first-run setup asks for it, so nobody else can become the first administrator |
| `NUXT_ATELIER_AUTH_TRUST_PROXY` | `true` behind a reverse proxy that sets `X-Forwarded-For`, so sign-in limits see each visitor's address. Leave it `false` when the container is reached directly. |

## Database

PostgreSQL 18, in the `db` service, with its data in the `postgres` volume. The app waits for it to accept connections before starting. Without Compose, the image uses SQLite in `/app/.data`: mount a volume there.

## Migrations on deploy

The image sets `NUXT_ATELIER_MIGRATIONS_AUTO_APPLY=true`: the server applies pending migrations when it starts. With several containers starting at once, apply them as a deploy step instead, before the new version starts, with `npx atelier migrate apply` and the production `NUXT_ATELIER_DATABASE_URL`, from your checkout or CI. See [Migrations](/reference/migrations#in-production).

## Media storage

Uploads go to `/app/.data/uploads`, in the `uploads` volume, so they outlive the container. Back the volume up with the database: see [backup](/deployment/backup).

## Scheduled jobs

Background jobs run in the server process, on Nitro's scheduler, every minute by default. When the container stops, running jobs get 10 seconds to finish; `stop_grace_period: 15s` leaves them that time.

## Real-time

The server serves the admin's WebSocket itself: edits, locks and comments are pushed to other editors at once. A reverse proxy in front must pass WebSocket connections through (Caddy and Traefik do by default).

## Limitations

| Limitation | Instead |
|---|---|
| Uploads in a volume belong to one host: containers on several hosts can't share them | [S3-compatible storage](/reference/media#s3-compatible-storage-and-cloudflare-r2) |
| SQLite (the image without Compose) serves one container | PostgreSQL, as in `compose.yml` |
| Several containers applying migrations as they start | apply them once as a deploy step with `atelier migrate apply` |
