[Dokploy](https://dokploy.com) and [Coolify](https://coolify.io) build and run Docker Compose projects from your Git repository, behind their own proxy with HTTPS. They use the same files as the [Docker guide](/deployment/docker): `Dockerfile`, `.dockerignore`, `compose.yml` and the app's `nuxt.config.ts`, in your repository's root.

## Build command and preset

The preset is Nuxt's default, the Node server, built by the Dockerfile. The platform runs `docker compose` on `compose.yml` for each deploy:

- **Dokploy:** in a project, create a **Compose** service from your repository, with `compose.yml` as the compose path.
- **Coolify:** add a resource from your repository, with the **Docker Compose** build pack and `compose.yml` as its file.

Then add your domain to the `app` service, on port `3000`, with HTTPS, and deploy. Turn on deploys on push to deploy every change.

For SQLite instead of PostgreSQL, deploy the `Dockerfile` alone (Dokploy: an **Application** with the **Dockerfile** build type; Coolify: the **Dockerfile** build pack), with a volume at `/app/.data`.

## Configuration files

Docker's files, unchanged:

<!-- file: docker/nuxt.config.ts -->
```ts [nuxt.config.ts]
// Docker and Docker Compose: Nuxt's default Node server, configured from the environment (compose.yml, .env).
// PostgreSQL needs its driver in your app: npm install pg
export default defineNuxtConfig({
  modules: ['nuxt-atelier', '@nuxt-atelier/admin'],
  compatibilityDate: '2026-10-01',
})
```

<!-- file: docker/Dockerfile -->
```dockerfile [Dockerfile]
# Nuxt Atelier in a container. Build from your app's root: docker build -t my-site .
# It installs with Bun, from bun.lock when there is one: with another package manager, swap the install line.
FROM oven/bun:1.4.4 AS bun

FROM node:24-slim AS build
COPY --from=bun /usr/local/bin/bun /usr/local/bin/bun
WORKDIR /app
COPY package.json bun.lock* ./
RUN bun install --frozen-lockfile
COPY . .
RUN bun run build

FROM node:24-slim
# SQLite and uploads live in /app/.data: mount a volume there so they outlive the container.
# NUXT_ATELIER_DATABASE_URL set at run time (compose.yml) points the server at PostgreSQL instead.
ENV NODE_ENV=production HOST=0.0.0.0 PORT=3000 \
    NUXT_ATELIER_DATABASE_URL=file:/app/.data/atelier.sqlite \
    NUXT_ATELIER_STORAGE_DIR=/app/.data/uploads \
    NUXT_ATELIER_MIGRATIONS_AUTO_APPLY=true
WORKDIR /app
COPY --from=build --chown=node:node /app/.output .output
RUN mkdir -p /app/.data && chown node:node /app/.data
USER node
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s \
  CMD ["node", "-e", "fetch('http://127.0.0.1:3000/api/_atelier/health/ready').then(r => process.exit(r.ok ? 0 : 1), () => process.exit(1))"]
CMD ["node", ".output/server/index.mjs"]
```

<!-- file: docker/.dockerignore -->
```text [.dockerignore]
node_modules
.nuxt
.output
.data
.env
```

<!-- file: docker/compose.yml -->
```yaml [compose.yml]
# Nuxt Atelier with PostgreSQL. Copy .env.example to .env, fill it in, then: docker compose up -d --build
services:
  app:
    build: .
    restart: unless-stopped
    ports:
      - "3000:3000"
    environment:
      NUXT_ATELIER_DATABASE_URL: postgres://atelier:${POSTGRES_PASSWORD:?set POSTGRES_PASSWORD in .env}@db:5432/atelier
      NUXT_APP_SECRET: ${NUXT_APP_SECRET:?set NUXT_APP_SECRET in .env}
      NUXT_PUBLIC_ATELIER_SITE_URL: ${NUXT_PUBLIC_ATELIER_SITE_URL:?set NUXT_PUBLIC_ATELIER_SITE_URL in .env}
      NUXT_ATELIER_AUTH_SETUP_TOKEN: ${NUXT_ATELIER_AUTH_SETUP_TOKEN:-}
      NUXT_ATELIER_AUTH_TRUST_PROXY: ${NUXT_ATELIER_AUTH_TRUST_PROXY:-false}
    volumes:
      - uploads:/app/.data
    depends_on:
      db:
        condition: service_healthy
    # running jobs get 10 seconds to finish when the container stops
    stop_grace_period: 15s

  db:
    image: postgres:18-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: atelier
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?set POSTGRES_PASSWORD in .env}
      POSTGRES_DB: atelier
    volumes:
      - postgres:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U atelier -d atelier"]
      interval: 5s
      timeout: 5s
      retries: 10

volumes:
  uploads:
  postgres:
```

The platform's proxy reaches the `app` container itself, so its `ports` mapping isn't needed: remove it to keep port 3000 closed on the server.

## Environment variables

Set them in the service's environment settings, which the platform hands to `docker compose`:

<!-- file: docker/.env.example -->
```bash [.env.example]
# Copy to .env and fill in. `openssl rand -hex 32` makes each secret.
NUXT_APP_SECRET=
POSTGRES_PASSWORD=
NUXT_PUBLIC_ATELIER_SITE_URL=https://example.com
# First-run setup asks for this token until the first administrator exists
NUXT_ATELIER_AUTH_SETUP_TOKEN=
# true behind a reverse proxy that sets X-Forwarded-For (Dokploy, Coolify, Caddy, nginx, Traefik)
NUXT_ATELIER_AUTH_TRUST_PROXY=false
```

Set `NUXT_ATELIER_AUTH_TRUST_PROXY` to `true`: requests arrive through the platform's proxy, which sets `X-Forwarded-For`. The [Docker guide](/deployment/docker#environment-variables) describes each variable.

## Database

PostgreSQL 18, in the `db` service, with its data in the `postgres` volume. Both platforms can also run PostgreSQL as a database service of their own: to use one, remove the `db` service and the app's `depends_on` from `compose.yml`, and set the app's `NUXT_ATELIER_DATABASE_URL` there to the database's connection URL.

## Migrations on deploy

The image sets `NUXT_ATELIER_MIGRATIONS_AUTO_APPLY=true`: the new container applies pending migrations when it starts.

## Media storage

Uploads go to the `uploads` volume, mounted at `/app/.data`, which outlives each deploy.

## Scheduled jobs

Background jobs run in the server process, on Nitro's scheduler, every minute by default. Nothing to set up.

## Real-time

The admin's WebSocket goes through the platform's proxy, which passes WebSocket connections through: edits, locks and comments are pushed to other editors at once.

## Limitations

| Limitation | Instead |
|---|---|
| The `uploads` volume lives on one server: the app can't run on several | [S3-compatible storage](/reference/media#s3-compatible-storage-and-cloudflare-r2) |
| SQLite (the `Dockerfile` alone) serves one container | PostgreSQL, with `compose.yml` or the platform's database service |
