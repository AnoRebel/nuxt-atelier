[Vercel](https://vercel.com) runs your app's server as functions. A function keeps no files between requests, so the database is a server reached over the network and uploads go to Vercel Blob.

## Build command and preset

Import the repository in Vercel: it detects Nuxt, runs your `build` script (`nuxt build`), and Nitro picks the `vercel` preset by itself. Each push deploys. No `vercel.json` is needed: Nuxt Atelier adds its cron to the build output.

Building in GitHub Actions instead (and deploying the output from there)? Set `NITRO_PRESET=vercel` for the build: Nitro picks its preset from the environment, and there it sees GitHub Actions first.

## Configuration files

<!-- file: vercel/nuxt.config.ts -->
```ts [nuxt.config.ts]
// Vercel: the vercel preset, picked when building on Vercel. A function has no lasting disk: the database is a
// PostgreSQL or libSQL server, and uploads go to Vercel Blob (npm install pg @nuxt-atelier/storage-vercel-blob).
export default defineNuxtConfig({
  modules: ['nuxt-atelier', '@nuxt-atelier/admin', '@nuxt-atelier/storage-vercel-blob'],
  compatibilityDate: '2026-10-01',
  atelier: {
    storage: { driver: 'vercel-blob' },
    migrations: { autoApply: true },
    auth: { trustProxy: true }, // Vercel sets X-Forwarded-For
  },
})
```

Install the database driver and the storage driver in your app:

```bash
npm install pg @nuxt-atelier/storage-vercel-blob
```

## Environment variables

Set them in the project's settings, for Production (and Preview, with another database):

<!-- file: vercel/.env.example -->
```bash [.env.example]
# The project's environment variables (Settings, Environment Variables). `openssl rand -hex 32` makes a secret.
NUXT_APP_SECRET=
NUXT_PUBLIC_ATELIER_SITE_URL=https://example.com
NUXT_ATELIER_DATABASE_URL=postgres://user:password@host:5432/atelier
# The cron that runs background jobs sends CRON_SECRET: both hold the same value
CRON_SECRET=
NUXT_ATELIER_JOBS_SECRET=
# First-run setup asks for this token until the first administrator exists
NUXT_ATELIER_AUTH_SETUP_TOKEN=
# Set by connecting a Blob store to the project
BLOB_READ_WRITE_TOKEN=
```

| Variable | Value |
|---|---|
| `NUXT_APP_SECRET` | at least 32 random characters (`openssl rand -hex 32`) |
| `NUXT_PUBLIC_ATELIER_SITE_URL` | the site's public URL |
| `NUXT_ATELIER_DATABASE_URL` | the database's URL |
| `CRON_SECRET`, `NUXT_ATELIER_JOBS_SECRET` | the same random value: Vercel's cron sends it, the trigger endpoint checks it |
| `NUXT_ATELIER_AUTH_SETUP_TOKEN` | optional: first-run setup asks for it, so nobody else can become the first administrator |
| `BLOB_READ_WRITE_TOKEN` | set by Vercel when you connect a Blob store to the project |

## Database

A database server: PostgreSQL (`postgres://…`, with `pg`), or libSQL and Turso (`libsql://…?authToken=…`, nothing to install). A SQLite file doesn't work: it would be lost with the function.

## Migrations on deploy

`migrations.autoApply` in `nuxt.config.ts`: a new deployment applies pending migrations when its server starts. To apply them as a step before deploying instead, run `npx atelier migrate apply` with the production `NUXT_ATELIER_DATABASE_URL` from CI, and remove `autoApply`.

## Media storage

[Vercel Blob](/reference/media#vercel-blob): connect a Blob store to the project. Files are stored private and served by your app at the usual URLs.

## Scheduled jobs

The build adds a [Vercel Cron Job](https://vercel.com/docs/cron-jobs) that calls the [trigger endpoint](/reference/jobs#the-trigger-endpoint) on `jobs.schedule`, every minute by default. It needs `CRON_SECRET` and `NUXT_ATELIER_JOBS_SECRET` set to the same value.

## Real-time

Vercel's functions don't hold WebSocket connections, so the admin polls every 20 seconds instead: other editors' edits, locks and comments appear, only later.

## Limitations

| Limitation | Instead |
|---|---|
| No lasting disk: a SQLite file and local uploads are lost | a PostgreSQL or libSQL server, and Vercel Blob for uploads |
| On the Hobby plan, a cron that runs more than once a day fails the deploy | the Pro plan; or `jobs.schedule` set to once a day, or to `false` with a scheduler calling the [trigger endpoint](/reference/jobs#the-trigger-endpoint) |
| No WebSocket: the admin polls every 20 seconds | a platform with a server, like [Docker](/deployment/docker) or [Fly.io](/deployment/fly), for changes pushed at once |
