title: Deno

Nitro builds a server for [Deno](https://deno.com) with the `deno-server` preset. It runs everything a Node server does: SQLite, uploads on disk, background jobs and the admin's real-time connection.

## Build command and preset

Set the `deno-server` preset in `nuxt.config.ts` (or `NITRO_PRESET=deno_server` at build), build with Node, and start the output with Deno:

```bash
npm run build
deno run --allow-net --allow-read --allow-write --allow-env --allow-sys --allow-ffi --unstable-byonm --unstable-node-globals .output/server/index.mjs
```

Use this command rather than the `start` task the preset writes to `.output/deno.json`: that one lacks `--allow-ffi` and `--allow-sys`, which SQLite's driver needs to load.

## Configuration files

<!-- file: deno/nuxt.config.ts -->
```ts [nuxt.config.ts]
// Deno: the server built for Deno's runtime (the deno-server preset), configured from the environment.
export default defineNuxtConfig({
  modules: ['nuxt-atelier', '@nuxt-atelier/admin'],
  compatibilityDate: '2026-10-01',
  nitro: { preset: 'deno-server' },
})
```

<!-- file: deno/Dockerfile -->
```dockerfile [Dockerfile]
# Nuxt Atelier on Deno, in a container. Build from your app's root: docker build -t my-site .
FROM oven/bun:1.4.4 AS bun

# Nuxt builds on Node; the server it builds runs on Deno
FROM node:24-slim AS build
COPY --from=bun /usr/local/bin/bun /usr/local/bin/bun
WORKDIR /app
COPY package.json bun.lock* ./
RUN bun install --frozen-lockfile
COPY . .
RUN bun run build

FROM denoland/deno:2.9.8
# SQLite and uploads live in /app/.data: mount a volume there so they outlive the container
ENV NODE_ENV=production HOST=0.0.0.0 PORT=3000 \
    NUXT_ATELIER_DATABASE_URL=file:/app/.data/atelier.sqlite \
    NUXT_ATELIER_STORAGE_DIR=/app/.data/uploads \
    NUXT_ATELIER_MIGRATIONS_AUTO_APPLY=true
WORKDIR /app
COPY --from=build --chown=deno:deno /app/.output .output
RUN mkdir -p /app/.data && chown deno:deno /app/.data
USER deno
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s \
  CMD ["deno", "eval", "fetch('http://127.0.0.1:3000/api/_atelier/health/ready').then(r => Deno.exit(r.ok ? 0 : 1), () => Deno.exit(1))"]
# SQLite's driver is a native module: it needs --allow-ffi and --allow-sys besides the preset's own permissions
CMD ["deno", "run", "--allow-net", "--allow-read", "--allow-write", "--allow-env", "--allow-sys", "--allow-ffi", "--unstable-byonm", "--unstable-node-globals", ".output/server/index.mjs"]
```

Use the [Docker guide's](/deployment/docker#configuration-files) `.dockerignore` with it. Then:

```bash
docker build -t my-site .
docker run -p 3000:3000 -v my-site-data:/app/.data -e NUXT_APP_SECRET=… -e NUXT_PUBLIC_ATELIER_SITE_URL=https://example.com my-site
```

On your own server, use the [VPS guide's](/deployment/vps) systemd unit with the `deno run` command above as `ExecStart`, with the full path to `deno`.

## Environment variables

| Variable | Value |
|---|---|
| `NUXT_APP_SECRET` | at least 32 random characters (`openssl rand -hex 32`). The server won't start without it. |
| `NUXT_PUBLIC_ATELIER_SITE_URL` | the site's public URL |
| `NUXT_ATELIER_AUTH_SETUP_TOKEN` | optional: first-run setup asks for it, so nobody else can become the first administrator |
| `NUXT_ATELIER_AUTH_TRUST_PROXY` | `true` behind a reverse proxy that sets `X-Forwarded-For` |

The image sets the database, the upload directory and automatic migrations, in `/app/.data`.

## Database

SQLite, in `/app/.data/atelier.sqlite`: mount a volume at `/app/.data`. For PostgreSQL, install `pg`, rebuild, and set `NUXT_ATELIER_DATABASE_URL`, as in the [Docker guide](/deployment/docker).

## Migrations on deploy

The image sets `NUXT_ATELIER_MIGRATIONS_AUTO_APPLY=true`: the server applies pending migrations when it starts.

## Media storage

Uploads go to `/app/.data/uploads`, on the volume.

## Scheduled jobs

Background jobs run in the server process, on Nitro's scheduler, every minute by default. On `SIGTERM` or `SIGINT`, running jobs get 10 seconds to finish.

## Real-time

The Deno server serves the admin's WebSocket itself: edits, locks and comments are pushed to other editors at once.

## Limitations

| Limitation | Instead |
|---|---|
| The preset's `deno task start` can't load SQLite's driver | the `deno run` command above, with `--allow-ffi` and `--allow-sys` |
| SQLite and the uploads volume serve one server | PostgreSQL and [S3-compatible storage](/reference/media#s3-compatible-storage-and-cloudflare-r2) |
