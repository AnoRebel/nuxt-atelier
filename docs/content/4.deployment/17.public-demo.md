---
title: A public demo
description: Let anyone try your site's admin and visual editor, each in a copy of their own that's deleted after use.
---

Demo mode turns a site into a public demo: every visitor who starts one gets a copy of the site to change as they like, signed in as its administrator. Their changes show to them alone, never to the site or to other visitors, and the copy is deleted once they leave. Nuxt Atelier's own [live demo](/getting-started/introduction) runs this way.

![The home page of Rayleigh, the site the live demo runs](/media/tutorial-home.webp)

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-atelier', '@nuxt-atelier/admin', '@nuxt-atelier/editor'],
  atelier: {
    demo: {
      enabled: true,
      idleTimeout: 1800, // seconds without a request before a copy is deleted
      frameAncestors: ['https://docs.example.com'], // sites that may show it in a frame
    },
  },
})
```

## How it works

- **The site is the template.** Its database holds what every demo starts from: fill it as you would any site (the [Rayleigh example](https://github.com/AnoRebel/nuxt-atelier/tree/main/examples/rayleigh) seeds itself on first start). Visitors can't change it: in demo mode the CMS API takes no change outside a demo, not even a sign-in.
- **A demo is a copy.** `/api/_atelier/demo/start?to=/admin` copies the database (SQLite's `VACUUM INTO`), signs the visitor in to the copy as a demo administrator, and takes them to `to`. Every request of theirs then reads and writes their copy: the API, the admin, the visual editor, and the site's pages as they see them.
- **Copies don't last.** One idle for `idleTimeout` seconds is deleted; so is the oldest idle one when `maxSessions` are open. A visitor ends theirs with `DELETE /api/_atelier/demo`. One address may have `perAddress` open at once.
- **Nothing is kept.** Demos can't upload or delete files (image sizes of the template's images are still made), and background jobs run on the template only, so a demo sends no email and calls no webhook.

Demo mode needs an SQLite database (each copy is a file in the system's temporary directory) and the built-in auth. It's for a public demo only: never turn it on for a site whose content matters.

## Showing it in your docs

Frame the start URL in your docs, with your docs' origin in `frameAncestors`. Start the demo when the reader asks, not on page load, so a page view doesn't make a copy:

```vue
<iframe src="https://demo.example.com/api/_atelier/demo/start?to=%2Fadmin%2Fedit%3Ftype%3Dhome" title="The visual editor, live" />
```

The demo's cookies only reach it in a frame when the docs and the demo are the same site (subdomains of one domain), as browsers don't send cookies to other sites' frames.
