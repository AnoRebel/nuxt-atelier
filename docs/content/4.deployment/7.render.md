title: Render
description: Deploy Nuxt Atelier on Render from a Blueprint, with PostgreSQL and a disk for uploads.

[Render](https://render.com) builds your app from its repository and runs it as a web service. A Blueprint, `render.yaml`, describes the service, its disk for uploads, and a PostgreSQL database.

## Build command and preset

The preset is `render_com`, Nitro's Node server for Render, set by `SERVER_PRESET` in `render.yaml`. Render runs `npm install && npm run build`, then `node .output/server/index.mjs`.

Commit `render.yaml`, then in Render's dashboard create a **Blueprint** from your repository. Render asks for the values marked `sync: false`, and deploys each push.

## Configuration files

<!-- file: render/render.yaml -->
```yaml [render.yaml]
# Nuxt Atelier on Render: a web service with a disk for uploads, and a PostgreSQL database (a Blueprint).
services:
  - type: web
    name: my-site
    runtime: node
    buildCommand: npm install && npm run build
    startCommand: node .output/server/index.mjs
    healthCheckPath: /api/_atelier/health/ready
    envVars:
      - key: SERVER_PRESET
        value: render_com
      - key: NODE_VERSION
        value: "24"
      - key: NUXT_ATELIER_DATABASE_URL
        fromDatabase:
          name: my-site-db
          property: connectionString
      - key: NUXT_ATELIER_STORAGE_DIR
        value: /var/data/uploads
      - key: NUXT_ATELIER_MIGRATIONS_AUTO_APPLY
        value: "true"
      - key: NUXT_ATELIER_AUTH_TRUST_PROXY
        value: "true"
      - key: NUXT_APP_SECRET
        generateValue: true
      - key: NUXT_PUBLIC_ATELIER_SITE_URL
        sync: false
      - key: NUXT_ATELIER_AUTH_SETUP_TOKEN
        generateValue: true
    disk:
      name: uploads
      mountPath: /var/data
      sizeGB: 1

databases:
  - name: my-site-db
    databaseName: atelier
    user: atelier
```

<!-- file: render/nuxt.config.ts -->
```ts [nuxt.config.ts]
// Render: Nuxt's Node server (the render-com preset, from SERVER_PRESET in render.yaml), configured from the
// service's environment. PostgreSQL needs its driver in your app: npm install pg
export default defineNuxtConfig({
  modules: ['nuxt-atelier', '@nuxt-atelier/admin'],
  compatibilityDate: '2026-10-01',
})
```

PostgreSQL needs its driver in your app: `npm install pg`.

## Environment variables

| Variable | Value |
|---|---|
| `NUXT_APP_SECRET` | generated by Render |
| `NUXT_PUBLIC_ATELIER_SITE_URL` | the site's public URL, asked for when the Blueprint is created |
| `NUXT_ATELIER_AUTH_SETUP_TOKEN` | generated by Render: copy it from the service's environment for first-run setup |
| `NUXT_ATELIER_DATABASE_URL` | the database's connection string |
| `NUXT_ATELIER_STORAGE_DIR` | the upload directory, on the disk |
| `NUXT_ATELIER_AUTH_TRUST_PROXY` | `true`: requests arrive through Render's proxy |
| `SERVER_PRESET`, `NODE_VERSION` | the Nitro preset, and Node 24 |

## Database

Render PostgreSQL, `my-site-db`. Its connection string becomes `NUXT_ATELIER_DATABASE_URL`.

## Migrations on deploy

`NUXT_ATELIER_MIGRATIONS_AUTO_APPLY=true`: the server applies pending migrations when it starts. On a paid instance, a `preDeployCommand: npx atelier migrate apply` applies them as a step instead, before the new version takes traffic.

## Media storage

Uploads go to `/var/data/uploads`, on the `uploads` disk mounted at `/var/data`. The rest of the service's filesystem is lost at each deploy.

## Scheduled jobs

Background jobs run in the server process, on Nitro's scheduler, every minute by default. Nothing to set up.

## Real-time

The server serves the admin's WebSocket itself: edits, locks and comments are pushed to other editors at once.

## Limitations

| Limitation | Instead |
|---|---|
| A disk needs a paid instance; a free one loses uploads at each deploy | a paid instance, or [S3-compatible storage](/reference/media#s3-compatible-storage-and-cloudflare-r2) without the disk |
| A service with a disk runs one instance, and deploys with a short downtime | S3-compatible storage without the disk, to scale and deploy without downtime |
| A free instance sleeps after 15 minutes without visitors, and runs no jobs while asleep | a paid instance, or a scheduler calling the [trigger endpoint](/reference/jobs#the-trigger-endpoint) |
| A free database is deleted after 30 days and a grace period | a paid database plan |
