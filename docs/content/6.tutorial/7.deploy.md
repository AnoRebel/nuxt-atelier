The migrations `nuxt dev` wrote while you built, in `server/atelier/migrations/`, go with the app: commit them. Production needs a secret of at least 32 characters in `NUXT_APP_SECRET` (`openssl rand -hex 32`): it seals sessions and signs preview links, and the server won't start without it. Go through the [security checklist](/deployment/security) before going live.

## In a container

The image builds the app, then keeps only its output. The database and uploads live in `/app/.data`: mount a volume there so they outlive the container. Migrations apply when the server starts.

<!-- file: Dockerfile -->
```dockerfile [Dockerfile]
# Rayleigh in a container: docker build -t rayleigh . && docker run -p 3000:3000 -v rayleigh-data:/app/.data rayleigh
# (for your own copy of the app, installed from npm; in this repository, the packages come from the workspace)
FROM oven/bun:1.4.4 AS bun

FROM node:26-slim AS build
COPY --from=bun /usr/local/bin/bun /usr/local/bin/bun
WORKDIR /app
COPY package.json bun.lock* ./
RUN bun install --frozen-lockfile
COPY . .
RUN bun run build

FROM node:26-slim
# the database and uploads live in /app/.data: mount a volume there so they outlive the container
ENV NODE_ENV=production HOST=0.0.0.0 PORT=3000 \
    NUXT_ATELIER_DATABASE_URL=file:/app/.data/rayleigh.sqlite \
    NUXT_ATELIER_STORAGE_DIR=/app/.data/uploads \
    NUXT_ATELIER_MIGRATIONS_AUTO_APPLY=true
WORKDIR /app
COPY --from=build --chown=node:node /app/.output .output
RUN mkdir -p /app/.data && chown node:node /app/.data
USER node
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s \
  CMD ["node", "-e", "fetch('http://127.0.0.1:3000/api/_atelier/health/ready').then(r => process.exit(r.ok ? 0 : 1), () => process.exit(1))"]
CMD ["node", ".output/server/index.mjs"]
```

<!-- file: .dockerignore -->
```text [.dockerignore]
node_modules
.nuxt
.output
.data
.steps
```

```bash
docker build -t rayleigh .
docker run -p 3000:3000 -v rayleigh-data:/app/.data -e NUXT_APP_SECRET=… rayleigh
```

The health check asks `/api/_atelier/health/ready`, which answers 503 while the database is out of reach.

## On Dokploy

[Dokploy](https://dokploy.com) builds and runs the same image from your repository:

1. Create a project, and in it an **Application** from your Git repository, with the **Dockerfile** build type.
2. Under **Environment**, set `NUXT_APP_SECRET`, and `NUXT_PUBLIC_ATELIER_SITE_URL` to the site's address.
3. Under **Advanced → Volumes**, mount a volume at `/app/.data`.
4. Under **Domains**, add yours on port `3000`, with HTTPS.
5. **Deploy**, and turn on auto-deploy to deploy every push.

## On Cloudflare Workers, with D1

On Workers, the database is [D1](/deployment/cloudflare-workers) and the uploads go to R2, since a Worker has no disk. Create the database, and put its id in `wrangler.json`:

```bash
bunx wrangler d1 create rayleigh
```

<!-- file: wrangler.json -->
```json [wrangler.json]
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "name": "rayleigh",
  "main": ".output/server/index.mjs",
  "compatibility_date": "2026-10-01",
  "compatibility_flags": ["nodejs_compat"],
  "assets": { "directory": ".output/public", "binding": "ASSETS" },
  "triggers": { "crons": ["* * * * *"] },
  "d1_databases": [
    { "binding": "DB", "database_name": "rayleigh", "database_id": "<your D1 database id>" }
  ],
  "vars": {
    "NUXT_ATELIER_DATABASE_URL": "d1:DB",
    "NUXT_ATELIER_MIGRATIONS_AUTO_APPLY": "true"
  }
}
```

The `triggers` cron wakes the Worker every minute to run [background jobs](/reference/jobs), scheduled publishing among them: a Worker only runs when something calls it.

Uploads need [S3-compatible storage](/reference/media#s3-compatible-storage-and-cloudflare-r2): add `@nuxt-atelier/storage-s3`, set `atelier.storage.driver` to `'s3'`, and give it an R2 bucket's keys as Worker secrets. Then build for Workers and deploy:

```bash
NITRO_PRESET=cloudflare-module bun run build
bunx wrangler secret put NUXT_APP_SECRET
bunx wrangler deploy
```

D1 is reachable only from inside the Worker, so migrations are applied there too (`NUXT_ATELIER_MIGRATIONS_AUTO_APPLY`), on the first write after each deploy: see [what D1 can and can't do](/deployment/cloudflare-workers#d1-and-transactions).

## The demo content

The example in the repository also fills an empty database with Rayleigh's demo content: its pages, posts, contact form and images, from `seed/`, by `server/middleware/seed.ts`. It's a convenience for trying the example; you don't need it for your own site.
