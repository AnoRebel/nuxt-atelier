This tutorial builds **Rayleigh**, a minimalistic portfolio with a blog, from an empty Nuxt app. Each chapter adds one part, and ends with a site that runs:

1. **Setup**: the app, its look, and a home page made of blocks
2. [**The portfolio**](/tutorial/portfolio): a gallery block whose images open full screen
3. [**Header and footer**](/tutorial/layout): a menu, social links and dark mode, edited as site settings
4. [**The about page**](/tutorial/about): pages at their own URLs, with text and image blocks
5. [**The blog**](/tutorial/blog): posts, a list of them with pages, and a layout of their own
6. [**The contact form**](/tutorial/contact): a form editors build, spam protection and email
7. [**Deployment**](/tutorial/deploy): Docker, Dokploy, and Cloudflare with D1

Rayleigh was designed by Muris Ceman as the template and tutorial for [Pruvious](https://pruvious.com), a CMS for Nuxt; this tutorial rebuilds it on Nuxt Atelier, with his design and demo content (MIT). The finished app is [`examples/rayleigh`](https://github.com/AnoRebel/nuxt-atelier/tree/main/examples/rayleigh) in the repository, and every code block here is that app's code at that chapter: the repository's tests build each chapter's state, so what you copy works.

## Create the app

You need [Bun](https://bun.sh) or Node.js 24 or later. Create a Nuxt app and add Nuxt Atelier, its admin, its visual editor, and Tailwind CSS:

```bash
bunx nuxi@latest init rayleigh
cd rayleigh
bun add nuxt-atelier @nuxt-atelier/admin @nuxt-atelier/editor tailwindcss @tailwindcss/vite sharp
bun add -d drizzle-kit@1.0.0-rc.5
```

`sharp` makes the image sizes pages ask for: without it, images are served as uploaded. `drizzle-kit` writes database migrations as your content types change, on your machine only ([why](/getting-started/installation#why-drizzle-kit-is-optional)). Your `package.json` ends up like this one (with versions):

<!-- file: package.json -->
```json [package.json]
{
  "name": "@nuxt-atelier/example-rayleigh",
  "private": true,

  "license": "MIT",
  "scripts": {
    "dev": "nuxt dev",
    "build": "nuxt build",
    "preview": "nuxt preview",
    "migrate": "atelier migrate generate"
  },
  "dependencies": {
    "@nuxt-atelier/admin": "workspace:*",

    "drizzle-kit": "catalog:db"
  }
}
```

## Configure Nuxt

The three modules give the app its content schema and API, the admin at `/admin`, and the visual editor. Every page of this site is content, served by Nuxt Atelier's catch-all page, so there's no `app/pages/` directory: `pages: true` turns Nuxt's router on without one.

<!-- file: nuxt.config.ts -->
```ts [nuxt.config.ts]
import tailwindcss from '@tailwindcss/vite'

// Rayleigh: a portfolio with a blog, built on Nuxt Atelier. Content lives in server/atelier/, the look in app/.
export default defineNuxtConfig({
  modules: ['nuxt-atelier', '@nuxt-atelier/admin', '@nuxt-atelier/editor'],
  // every page is an entry, served by Nuxt Atelier's catch-all page: the router without an app/pages/
  pages: true,
  app: {
    head: {
      htmlAttrs: { lang: 'en' },
      link: [
        { rel: 'icon', type: 'image/svg+xml', href: '/favicon.svg' },
        { rel: 'preconnect', href: 'https://fonts.googleapis.com' },
        { rel: 'preconnect', href: 'https://fonts.gstatic.com', crossorigin: '' },
        { rel: 'stylesheet', href: 'https://fonts.googleapis.com/css2?family=Lato:ital,wght@0,400;0,700;1,400;1,700&family=Poppins:wght@500&display=swap' },
      ],
    },
  },
  css: ['~/assets/css/main.css'],
  compatibilityDate: '2026-10-01',
  vite: { plugins: [tailwindcss()] },
  atelier: {
    database: { url: 'file:.data/rayleigh.sqlite' }, // NUXT_ATELIER_DATABASE_URL in production
    seo: { titleTemplate: '%s | Rayleigh' },
  },
})
```

The database is an SQLite file in `.data/` while you build. In production, `NUXT_ATELIER_DATABASE_URL` points it elsewhere ([chapter 7](/tutorial/deploy)).

## The look

Rayleigh's colours, fonts and type sizes become Tailwind's theme. Its breakpoints are maximum widths (`tp:` up to a tablet in portrait, `ph:` up to a phone), and `dark:` applies when the visitor chose dark mode or, until they choose, when their system is dark: [chapter 3](/tutorial/layout) adds the switch.

<!-- file: app/assets/css/main.css -->
```css [app/assets/css/main.css]
@import "tailwindcss";

/* Dark when the visitor chose it (`.dark` on <html>, from a cookie) or, with no choice, when their system is */
@custom-variant dark {
  &:where(.dark, .dark *) {
    @slot;
  }
  @media (prefers-color-scheme: dark) {
    &:where(:root:not(.light), :root:not(.light) *) {
      @slot;
    }
  }
}
@custom-variant hocus (&:hover, &:focus-visible);
/* Rayleigh's breakpoints are maximum widths: laptop, tablet landscape, tablet portrait, phone */
@custom-variant lp (@media (max-width: 1440px));
@custom-variant tl (@media (max-width: 1199px));
@custom-variant tp (@media (max-width: 1023px));
@custom-variant ph (@media (max-width: 767px));

@theme {
  --color-heading: #010203;
  --color-copy: #234345;
  --color-accent: #268baa;
  --color-border: #e2e4e8;
  --color-dim: #59797b;
  --font-sans: Lato, ui-sans-serif, system-ui, sans-serif;
  --font-heading: Poppins, ui-sans-serif, system-ui, sans-serif;
  --text-vs: 0.8125rem;
  --text-vs--line-height: 1.5;
  --text-sm: 0.875rem;
  --text-sm--line-height: 1rem;
  --text-post-title: 2rem;
  --text-post-title--line-height: 1.5;
  --container-content: 48.75rem;
}

@layer base {
  body {
    @apply text-copy transition duration-300 dark:bg-heading dark:text-white/80;
  }
  h1, h2, h3 {
    @apply font-heading font-medium text-heading transition duration-300 dark:text-white;
  }
  h1 {
    @apply text-[2rem] ph:text-[1.5rem];
  }
  h2 {
    @apply text-[1.5rem] ph:text-[1.25rem];
  }
  h3 {
    @apply text-[1.25rem] ph:text-[1rem];
  }
}
```

## A home page

Content types live in `server/atelier/`. The home page is a **singleton**, content there's one of, and its route `/` makes it the page at the site's root. Its `content` is a list of blocks:

<!-- file: server/atelier/singletons/home.ts -->
```ts [server/atelier/singletons/home.ts]
import { blocks, defineSingleton, text } from '#atelier/server'

// The home page, at /
export default defineSingleton({
  label: 'Home page',
  route: { pattern: '/' },
  fields: {
    title: text({ required: true }),
    content: blocks(),
  },
})
```

Blocks are Vue components in `app/blocks/`. `defineBlock` names one for the editor, and its props are its fields: `text()` is a line of text, `required` makes it so. `<AtelierField>` marks where a field shows, so the visual editor can edit it right on the page.

<!-- file: app/blocks/PageIntro.vue -->
```vue [app/blocks/PageIntro.vue]
<script setup lang="ts">
import { defineBlock, text } from '#atelier'

defineBlock({ label: 'Page intro', icon: 'heading-1', description: 'The page\'s heading, with a line under it' })
defineProps({ title: text({ required: true }), kicker: text() })
</script>

<template>
  <SiteContainer>
    <div class="max-w-content space-y-2">
      <h1>
        <AtelierField name="title">
          {{ title }}
        </AtelierField>
      </h1>
      <p
        v-if="kicker"
        class="text-sm"
      >
        <AtelierField name="kicker">
          {{ kicker }}
        </AtelierField>
      </p>
    </div>
  </SiteContainer>
</template>
```

## Run it

```bash
bun run dev
```

Open [http://localhost:3000/admin](http://localhost:3000/admin) and create the first administrator. In **Home page**, set a title, add a **Page intro** block with "Welcome to Rayleigh", and choose **Publish**. [http://localhost:3000](http://localhost:3000) shows it.

![The admin's first screen, asking for the first administrator's name, email and password](/media/admin-setup.webp)

While you build, `nuxt dev` keeps the database in step with your content types: each change becomes a migration in `server/atelier/migrations/`, applied at once. Commit them with your code; [chapter 7](/tutorial/deploy) applies them in production. A change that would delete data, like removing a field, waits for you to confirm it with `bunx atelier migrate generate --drop`.
