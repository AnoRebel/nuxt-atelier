---
title: DevTools
description: Nuxt DevTools panels for your content schema, migrations, background jobs and the admin, in development.
---

`@nuxt-atelier/devtools` adds Nuxt Atelier to [Nuxt DevTools](https://devtools.nuxt.com) while you develop. It's a separate package, installed as a dev dependency, so nothing of it reaches production, and the core has no DevTools code.

```bash
bun add -d @nuxt-atelier/devtools
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-atelier', '@nuxt-atelier/admin', '@nuxt-atelier/devtools'],
  devtools: { enabled: true },
})
```

It registers only with `nuxt dev` and DevTools on: in a build, or with `devtools: { enabled: false }`, it does nothing.

## The panels

| Panel | Shows |
|---|---|
| **Atelier: schema** | every collection and singleton, their fields (type, required), whether they're versioned or routable, and the database tables they make |
| **Atelier: migrations** | the database (credentials hidden), the applied and pending migrations (what `atelier migrate status` says), and a schema change `nuxt dev` couldn't apply because it would delete data, with the `--drop` or `--rename` flag `atelier migrate generate` needs to confirm it |
| **Atelier: jobs** | background jobs, newest first: status, when they're due, attempts and the last error |
| **Atelier: admin** | the admin, in DevTools |
| **Atelier: actions** | **Apply pending migrations** to the dev database, and **Retry** for each failed job (the ten most recent) |

The panels read the database when they open: reopen one to refresh it.

## DevTools 3 and 4

DevTools 4 (on Vite DevTools) shows the panels as docks in the Nuxt group, and **Apply pending migrations** as the command `atelier:apply-migrations`. Nuxt 4.6 ships DevTools 3, which shows them as module tabs, with the actions in the **Atelier: actions** tab. Both register from Nuxt's own DevTools hooks, so the integration works with either, without the deprecation warnings of the older API.

## Security

The panels' page is served by the dev server only, at `/__atelier_devtools/<panel>`, and shows what the dev server already can: your schema, migration names and jobs, never content or credentials.

The actions change your dev database, so they run only through DevTools' own authorized connection. When `devtools.disableAuthorization` is set, which lets any browser that reaches the dev server use DevTools, the actions are off: the actions tab has none, and the command refuses.
