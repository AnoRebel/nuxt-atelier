## Typed helpers

In your app, `useAtelierQuery` and `useAtelierEntry` fetch content with SSR: they run on the server with the visitor's session, and refetch when their arguments change.

```vue [pages/news.vue]
<script setup lang="ts">
const { data } = await useAtelierQuery('articles', {
  filter: { category: { eq: 'news' } },
  sort: ['-publishedAt'],
  fields: ['title', 'publishedAt', 'author'],
  depth: 1,
})
</script>

<template>
  <article v-for="article in data?.items" :key="article.id">
    <h2>{{ article.data.title }}</h2>
  </article>
</template>
```

```ts
const { data: article } = await useAtelierEntry('articles', () => route.params.id as string, { depth: 1 })
```

In server code, `queryEntries` and `getEntry` from `#atelier/server` read the database directly. They don't check permissions: server code is trusted.

```ts [server/api/feed.get.ts]
import { queryEntries } from '#atelier/server'

export default defineEventHandler(() => queryEntries('articles', { sort: ['-publishedAt'], limit: 10 }))
```

Everything is typed from your [content schema](/reference/content-schema): a filter or sort on a field the collection doesn't have, or a value outside a `select`'s options, is a type error. With `depth`, relations are typed as entries.

## Filters

A filter maps fields to conditions. Several fields, or several operators on one field, must all match:

```ts
{ category: { eq: 'news' }, views: { gte: 100, lt: 1000 } }
```

Group with `and` and `or`, nesting up to 5 levels:

```ts
{ or: [{ category: { eq: 'guides' } }, { and: [{ featured: { eq: true } }, { views: { gt: 500 } }] }] }
```

| Operator | Matches | Fields |
|---|---|---|
| `eq`, `ne` | equal, not equal | text, number, boolean, select, date and similar; relations |
| `gt`, `gte`, `lt`, `lte` | greater, less | text, number, date, select and similar (not boolean) |
| `contains` | text containing the value, case-insensitive; a list holding it | text, textarea, email, url, slug; multiSelect; relations |
| `in` | one of up to 100 values | as `eq` |
| `null` | `true`: empty; `false`: has a value | any |

Filters name top-level fields, or the system fields `_id`, `_createdAt`, `_updatedAt` and `_createdBy`. Rich text, JSON, objects, repeaters and blocks can only be filtered with `null`.

Relations filter by the related entry's id:

```ts
{ author: { eq: authorId } } // a single relation pointing to this author
{ tags: { contains: tagId } } // a many relation including this tag
{ author: { null: true } } // no author
```

Dates are ISO 8601 strings, so they compare as text: `{ publishedAt: { lt: '2026-12-01T00:00:00Z' } }`.

## Sorting

`sort` lists fields, `-` first for descending: `['-publishedAt', 'title']`. Empty values sort last in both directions, on every database. Entries with equal sort values are ordered by id, so pages never overlap.

## Selecting fields

`fields: ['title', 'author']` returns only those fields of each entry's data. The entry's `id`, `version` and timestamps are always there.

## Pages

A page has at most `limit` entries (default 20, at most `limits.maxPageSize`). `total` counts every entry matching the filter.

- **Cursor:** pass the previous page's `next` as `cursor` for the next page; `next` is `null` on the last one. Use the same filter and sort. A cursor page is stable while entries are added or removed.
- **Offset:** `offset: 40` skips 40 entries. Simpler, but entries added while paging shift the pages.

## Relations

`depth: 1` replaces relation ids with the entries they point to; `depth: 2` does the same inside those, up to `limits.maxRelationDepth`. Related entries are loaded in one query per collection per level, however many entries the page has.

## In the REST API

The [list endpoint](/reference/content-api#collections) takes the same query as URL parameters: `filter` is JSON, `sort` and `fields` are comma-separated.

```bash
curl -G https://example.com/api/_atelier/collections/articles \
  --data-urlencode 'filter={"category":{"eq":"news"}}' \
  --data-urlencode 'sort=-publishedAt' \
  --data-urlencode 'depth=1' \
  -H "authorization: Bearer $ATELIER_TOKEN"
```
