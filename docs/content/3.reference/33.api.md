## Composables

Auto-imported in the app.

### `useAtelierArea`

The area the calling block is rendered in, with the props its parent passes to the slot, or `null` for a
block at the top of a list. Slot props reach nested blocks only through this, never as their props or
attributes, so they can't collide with a block's fields.

```ts
useAtelierArea<P extends Record<string, unknown> = Record<string, unknown>>(): ComputedRef<AtelierArea<P> | null>
```

### `useAtelierConfig`

Public Nuxt Atelier runtime config (`runtimeConfig.public.atelier`).

```ts
useAtelierConfig()
```

### `useAtelierLocalePath`

Turns an entry's path into the URL it's served at in a locale, prefixed as the site's i18n module
wants: `localePath('/produkte/stuhl', 'de')` → `/de/produkte/stuhl`. Unchanged without an i18n module.

```ts
useAtelierLocalePath(): (path: string, locale: string) => string
```

### `useAtelierPreview`

Whether this render is an editing preview. Only then do `<AtelierBlocks>` and `<AtelierField>` add
the attributes the visual editor uses; public pages never carry them.

```ts
useAtelierPreview(): Ref<boolean>
```

### `useAtelierEntry`

One entry from the content API, with SSR. `depth` populates its relations; `locale` reads a localized one's translation.

```ts
useAtelierEntry<N extends CollectionName, D extends number | undefined = undefined>(name: N, id: MaybeRefOrGetter<string>, options?: { depth?: D, locale?: MaybeRefOrGetter<string | undefined> })
```

### `useAtelierQuery`

A page of a collection's entries from the content API, with SSR: `useFetch` under the hood, so it
renders on the server (with the visitor's session) and refetches when the query changes.

```ts
useAtelierQuery<N extends CollectionName, Q extends CollectionQuery<N> = CollectionQuery<N>>(name: N, query?: MaybeRefOrGetter<Q>)
```

### `useAtelierSingleton`

A singleton from the content API (site settings, a footer), with SSR: one request per page wherever it's
used, shared by key. `depth` populates its relations.

```ts
useAtelierSingleton<N extends keyof AtelierSingletons & string>(name: N, options?: { depth?: number })
```

### `useAtelierRouteEntry`

The entry served at the current URL, for the app's own layouts and components: the same request the
catch-all page makes (one fetch, shared by key), refetched when the route changes. `data` is null on
a URL no entry has, or one the visitor can't read; pass the collection's name for typed data.

Drafts show with `?_atelier=preview` for editors who can edit the type, and with a shared preview
link's `?_atelier_preview=<token>` for anyone, until it expires.

```ts
useAtelierRouteEntry<N extends CollectionName = CollectionName>()
```

### `useAtelierSiteSearch`

Site search over published content, with SSR (`useFetch`), refetching as the query changes. Nothing is
fetched for an empty query.

```ts
useAtelierSiteSearch(query: MaybeRefOrGetter<string>, options: { types?: MaybeRefOrGetter<string[] | undefined>, locale?: MaybeRefOrGetter<string | undefined>, limit?: MaybeRefOrGetter<number | undefined>, offset?: MaybeRefOrGetter<number | undefined> } = {})
```

### `<AtelierBlocks>`

`<AtelierBlocks :blocks="entry.data.content" />`: renders a block list. Each block's fields and options are its component's props; each nested area is the component's slot of the same name, so block components need nothing from Nuxt Atelier. Components load lazily, per block type.

| `blocks` | `BlockInstance[] \| null` | `() => []` |  |

## CLI

The `atelier` command, installed with `nuxt-atelier` (`bunx atelier`, `npx atelier`).

```text
Usage: atelier <command> [options]

Commands:
  init                     add secrets to .env and a first collection, where missing
  migrate generate         write a migration for schema changes to server/atelier/migrations/<dialect>/
  migrate apply            apply pending migrations to the database (--dry-run: rehearse them, keeping nothing)
  migrate status           list applied and pending migrations
  export <file>            write all content to a portable archive (gzipped when <file> ends in .gz)
  import <file>            load an archive into an empty, migrated database (any engine)
  user create-admin        create an administrator (--email, --name; a password is generated unless --password-stdin)
  user reset-password      set a user's password and sign them out everywhere (--email; generated unless --password-stdin)
  jobs list                background jobs, newest first (--status queued|running|failed)
  jobs retry <id>          queue a failed job again
  jobs run                 run due jobs now, on the running site (--url, default NUXT_PUBLIC_ATELIER_SITE_URL;
                           sends NUXT_ATELIER_JOBS_SECRET)
  search rebuild           index all published content for site search again, on the running site (--url, as
                           jobs run)

Options:
  --root <dir>          the Nuxt app (default: current directory)
  --dialect <name>      generate for sqlite, postgres or mysql (default: from the database URL)
  --name <name>         migration name
  --drop <c>[.<field>]  confirm deleting a removed collection or field and its data (repeatable)
  --rename <c>.<old>=<new> | <old c>=<new c>
                        declare a renamed field or collection, keeping its data (repeatable)
  --email, --name       for the user commands
  --password-stdin      read the password from standard input instead of generating one
  --status, --url       for the jobs commands

The database URL comes from NUXT_ATELIER_DATABASE_URL or the atelier.database.url option.
```
