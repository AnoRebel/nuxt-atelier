---
title: Webhooks
description: Tell other systems when content changes, with signed requests they can verify.
---

A webhook sends a `POST` to a URL of yours whenever content changes: rebuild a static site, refresh a search index, post to a chat. Administrators manage them through the API (and soon the admin).

## Creating a webhook

```http
POST /api/_atelier/webhooks
{ "url": "https://example.com/hooks/cms", "events": ["entry.published", "entry.unpublished"], "types": ["articles"] }
```

```json
{ "id": "3b1e…", "url": "https://example.com/hooks/cms", "events": ["entry.published", "entry.unpublished"], "types": ["articles"], "active": true, "secret": "whsec_Q3Jhe…" }
```

The `secret` is shown only in this answer: keep it with your receiver. It's stored encrypted, with a key derived from `NUXT_APP_SECRET`.

| Field | What it does |
|---|---|
| `url` | where to send events: `https://` (or `http://`) |
| `events` | any of `entry.saved` (a draft saved), `entry.published` (also every save in a type that isn't versioned), `entry.unpublished`, `entry.deleted`, and `form.submitted` (a [form](/reference/forms) submission: its `form`, `submission` id, `version`, `locale`; filter it by the type `atelier-forms`) |
| `types` | the collections and singletons it's for; leave it out for all |

`PATCH /api/_atelier/webhooks/<id>` changes `url`, `events`, `types` or `active` (`false` pauses it), `DELETE` removes it, and `GET /api/_atelier/webhooks/<id>/deliveries` lists the delivery attempts, newest first, with each response's status or the error. Changes are recorded in the [audit log](/reference/authentication#the-audit-log).

## What's sent

```http
POST /hooks/cms
content-type: application/json
webhook-id: msg_2f1c0a…
webhook-timestamp: 1794301234
webhook-signature: v1,K5oZfzN95Z9UVu1EsfQmfVNQhnkZ2pj9o9NDN/H/pI4=

{ "type": "entry.published", "timestamp": "2026-11-10T09:00:34.000Z", "data": { "type": "articles", "id": "8f1c…", "live": true } }
```

`data` names the entry; read it from the [content API](/reference/content-api) if you need its content. Each event has its own `webhook-id`, the same on every retry, so a receiver can ignore one it has already handled.

Deliveries go through the [job queue](/reference/jobs). A delivery that fails (an error, a timeout after 10 seconds, or an answer other than `2xx`) is retried with backoff, up to 8 attempts. Redirects aren't followed: answer with `2xx`. The delivery log keeps 30 days.

## Verifying the signature

Requests are signed per [Standard Webhooks](https://www.standardwebhooks.com), so its libraries verify them:

```ts
import { Webhook } from 'standardwebhooks'

const webhook = new Webhook(process.env.CMS_WEBHOOK_SECRET!) // whsec_…

export default defineEventHandler(async (event) => {
  const body = await readRawBody(event) ?? ''
  const payload = webhook.verify(body, getHeaders(event)) // throws when the signature or timestamp is wrong
  // …
})
```

Without a library: the signature is `v1,` and the base64 HMAC-SHA256 of `<webhook-id>.<webhook-timestamp>.<body>`, keyed by the base64-decoded part of the secret after `whsec_`. Compare it in constant time, and reject timestamps more than a few minutes old.

## Internal addresses

A webhook can't reach your own network by accident, or be used to probe it. A URL whose host is, or resolves to, a private, loopback, link-local or other internal address (`10.x`, `127.x`, `169.254.x`, `fd00::`, …) is refused when it's saved and again before every delivery, in case its DNS changed. To send to an internal service on purpose, allowlist its host:

```ts [nuxt.config.ts]
atelier: { webhooks: { allow: ['search.internal'] } }
```

On Cloudflare Workers there's no DNS lookup to check: addresses written in the URL, and `localhost`, are still refused, and Cloudflare doesn't route Workers' requests to private networks.
