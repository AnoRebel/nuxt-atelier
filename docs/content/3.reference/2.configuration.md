Options go under the `atelier` key in `nuxt.config.ts`. Every option is optional. Invalid values stop the build with a message naming the option, the value and what's accepted.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-atelier'],
  atelier: {
    database: { url: 'postgres://cms@localhost:5432/atelier' },
  },
})
```

## `database`

| Option | Type | Default | Description |
|---|---|---|---|
| `database.url` | string | `"file:.data/atelier.sqlite"` | Database URL: `file:` (SQLite), `libsql:` (libSQL/Turso), `d1:<binding>` (Cloudflare D1), `postgres:`, `mysql:` or `mariadb:`. Override at runtime with `NUXT_ATELIER_DATABASE_URL`. |

## `migrations`

| Option | Type | Default | Description |
|---|---|---|---|
| `migrations.autoApply` | boolean | `false` | Apply pending migrations when the production server starts. When off, run `atelier migrate apply`; until then CMS writes are refused. Override at runtime with `NUXT_ATELIER_MIGRATIONS_AUTO_APPLY`. |

## `storage`

| Option | Type | Default | Description |
|---|---|---|---|
| `storage.driver` | `"local"` | `"local"` | Media storage driver. |
| `storage.dir` | string | `".data/uploads"` | Upload directory, relative to the app root. Override at runtime with `NUXT_ATELIER_STORAGE_DIR`. |

## `auth`

| Option | Type | Default | Description |
|---|---|---|---|
| `auth.provider` | `"builtin"` | `"builtin"` | Authentication provider. |
| `auth.signInAttempts` | integer, 1–1000 | `10` | Failed sign-ins allowed per IP address and email within `auth.signInWindow`; then 429 until it ends. An email alone allows five times as many, so rotating addresses doesn't help. |
| `auth.signInWindow` | integer, 60–86400 | `900` | The sign-in rate limit window, in seconds. |
| `auth.trustProxy` | boolean | `false` | Take the client IP from `X-Forwarded-For`. Turn on only behind a proxy that sets it, or clients could spoof their address. |
| `auth.passkeys` | boolean | `false` | Let users of the built-in provider register passkeys and sign in with them. Needs `@simplewebauthn/server`. The relying party is the public site URL (`NUXT_PUBLIC_ATELIER_SITE_URL`). |

## `admin`

| Option | Type | Default | Description |
|---|---|---|---|
| `admin.base` | string | `"/admin"` | Path the admin is served under: a leading slash, no trailing slash, not under `/api`. |

## `revisions`

| Option | Type | Default | Description |
|---|---|---|---|
| `revisions.keep` | integer, 1–100000 | `50` | Revisions each entry keeps at least: its newest ones. Older ones are deleted once they're also older than `revisions.days`, except, in versioned types, those that were published. Checked daily, as a background job. |
| `revisions.days` | integer, 0–36500 | `30` | Days every revision is kept, however many there are. |

## `jobs`

| Option | Type | Default | Description |
|---|---|---|---|
| `jobs.schedule` | union | `"* * * * *"` | When the server runs due background jobs, as a cron expression, with Nitro's scheduled tasks (Node, Bun, Deno; Vercel Cron and Cloudflare Cron Triggers at build, which take 5 fields). `false` leaves it to the trigger endpoint, for platforms without scheduled tasks. |
| `jobs.triggerBudget` | integer, 1–900 | `25` | Seconds the job trigger endpoint (`POST /api/_atelier/jobs/run`) keeps starting jobs; the rest stay queued for the next call. Its secret is `NUXT_ATELIER_JOBS_SECRET`. |

## Runtime overrides

These take effect in a built app without rebuilding:

| Environment variable | Overrides |
|---|---|
| `NUXT_ATELIER_DATABASE_URL` | `database.url` |
| `NUXT_ATELIER_MIGRATIONS_AUTO_APPLY` | `migrations.autoApply` |
| `NUXT_ATELIER_STORAGE_DIR` | `storage.dir` |
| `NUXT_PUBLIC_ATELIER_SITE_URL` | the public site URL |
| `NUXT_APP_SECRET` | the session secret (Nuxt's `runtimeConfig.appSecret`) |
