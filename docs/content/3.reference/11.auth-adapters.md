An auth adapter answers who's signed in, signs people in and out, and manages users. The CMS's roles, [permissions](/reference/permissions), first-run setup and audit log work the same whichever adapter is in use.

## Better Auth

`@nuxt-atelier/auth-better-auth` runs [Better Auth](https://www.better-auth.com) on your CMS database, for OAuth providers, two-factor authentication, passkeys and the rest of its plugins.

```bash
npm i @nuxt-atelier/auth-better-auth better-auth
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-atelier', '@nuxt-atelier/auth-better-auth'],
})
```

Configure it in `server/atelier/auth.ts`:

```ts [server/atelier/auth.ts]
import { defineAtelierBetterAuth } from '@nuxt-atelier/auth-better-auth/config'
import { twoFactor } from 'better-auth/plugins'

export default defineAtelierBetterAuth({
  betterAuth: {
    appName: 'My site',
    socialProviders: {
      github: { clientId: process.env.GITHUB_CLIENT_ID!, clientSecret: process.env.GITHUB_CLIENT_SECRET! },
    },
    plugins: [twoFactor()],
  },
  // the CMS role for people who sign up or sign in with GitHub for the first time
  mapRole: user => user.email.endsWith('@my-company.com') ? 'editor' : null,
})
```

And declare its tables, so they're [migrated](/reference/migrations) with your content:

```ts [server/atelier/tables.ts]
import { betterAuthTables } from '@nuxt-atelier/auth-better-auth/config'
import { defineTables } from '#atelier/server'
import auth from './auth'

export default defineTables(betterAuthTables(auth))
```

`nuxt dev` creates them. Adding a plugin that has tables of its own, like `twoFactor()`, adds them to the next migration.

### What Nuxt Atelier sets

- **Database:** your CMS database, through Better Auth's Drizzle adapter. Its tables are named `atelier_ba_*`.
- **Routes:** `/api/auth/**`. OAuth callbacks go to `/api/auth/callback/<provider>`; register that URL with each provider.
- **Secret:** derived from `NUXT_APP_SECRET`, unless you set `betterAuth.secret`.
- **Base URL:** `NUXT_PUBLIC_ATELIER_SITE_URL`, unless you set `betterAuth.baseURL`.
- **Email and password:** on, so first-run setup and password sign-in work.

### Roles

The CMS role is a field on Better Auth's user. `mapRole` sets it when the user is created, from their email and name; `null` (the default for everyone) gives no role. A user without a role can sign in to Better Auth, but `GET /api/_atelier/auth/me` returns `null` and the CMS refuses them until an administrator gives them a role. Users created in the CMS get the role they're created with.

### Passkeys and two-factor

Use Better Auth's plugins: `twoFactor()` from `better-auth/plugins`, `passkey()` from `@better-auth/passkey`. Nuxt Atelier's own `auth.passkeys` option is for the built-in adapter only.

## Writing an auth adapter

An adapter implements `AuthAdapter` from `#atelier/server`:

| Member | Does |
|---|---|
| `name` | shown in errors |
| `getUser(event)` | the signed-in user `{ id, email, name, role }`, or `null` |
| `signIn(event, { email, password })` | starts a session (sets its cookies on `event.res.headers`) and returns the user; a `401` error for wrong credentials |
| `signOut(event)` | ends this request's session |
| `users.list()`, `users.get(id)` | users, with their role (`''` for none) |
| `users.create({ email, name?, role, password? })`, `users.update(id, changes)`, `users.delete(id)` | manage users; a password change should end the user's other sessions |
| `oauthProviders()` | optional: sign-in options for the login screen |

Register it from a Nitro plugin; it replaces the built-in adapter. The factory runs on first use:

```ts [server/plugins/auth.ts]
import { registerAuthAdapter } from '#atelier/server'
import { createSsoAdapter } from '../utils/sso-adapter'

export default () => {
  registerAuthAdapter(() => createSsoAdapter())
}
```

`registerAuthAdapter` checks the adapter has every member and names any that's missing.

### Storing your own tables

An adapter that needs tables declares them in `server/atelier/tables.ts`. They get migrations like content tables, on every engine:

```ts [server/atelier/tables.ts]
import { defineTables } from '#atelier/server'

export default defineTables({
  atelier_sso_links: {
    columns: {
      userId: { type: 'string', required: true, index: true },
      subject: { type: 'string', required: true, unique: true },
      linkedAt: { type: 'date', required: true },
    },
  },
})
```

Each table gets a string `id` primary key. Names start with `atelier_` (not `atelier_c_`, which is for collections). Column types are `string`, `number`, `boolean`, `date` and `json`; a column can be `required`, `unique`, `index`ed, a `bigint`, or reference another table with `references: { table, onDelete }`. Read and write them with `useAtelierTables()` and `useAtelierDatabase()`.
