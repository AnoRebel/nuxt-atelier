---
title: Lifecycle hooks
description: Run your own code before and after content is created, changed, published, deleted or read.
---

Hooks let your server code take part in every content operation: the content API, the admin, scheduled publishing, and your own calls to `useAtelierEntries()`. Register them in a server plugin with Nuxt's `useServerHooks()`; they're typed:

```ts [server/plugins/content.ts]
import { apiError } from '#atelier/server'
import { useServerHooks } from 'nuxt/server'

export default () => {
  const hooks = useServerHooks()

  // fill in a field, or refuse the save
  hooks.hook('atelier:beforeCreate', ({ type, data }) => {
    if (type !== 'articles')
      return
    data.slug ||= slugify(String(data.title))
    if (String(data.title).includes('lorem ipsum'))
      throw apiError(422, 'Replace the placeholder text first', { errors: [{ path: 'title', message: 'placeholder text' }] })
  })

  // tell another system
  hooks.hook('atelier:afterPublish', async ({ type, id, version }) => {
    await notifySearchIndex(type, id, version)
  })
}
```

## The hooks

| Hook | Runs | Gets |
|---|---|---|
| `atelier:beforeCreate` / `afterCreate` | creating an entry, or a singleton's first save | `type`, `id`, `actorId`; `data` and `publish` before, the saved `entry` after |
| `atelier:beforeUpdate` / `afterUpdate` | saving an existing entry | as above, with the `version` it was read at |
| `atelier:beforePublish` / `afterPublish` | publishing, including a save with `publish: true` and a scheduled publish | `type`, `id`, `actorId`, `version` |
| `atelier:beforeUnpublish` / `afterUnpublish` | taking it off the site | `type`, `id`, `actorId` |
| `atelier:beforeDelete` / `afterDelete` | deleting an entry | `type`, `id`, `actorId` |
| `atelier:formSubmitted` | after a [form](/reference/forms) submission is stored | `form` (its id), `submission` |
| `atelier:beforeRead` / `afterRead` | reading an entry, a singleton or a list | `type`, `stage` (`published` or `draft`); `id` or `query` before, the `entries` after |

`type` is the collection or singleton name, `id` the entry's id (a singleton's name for a singleton), `actorId` the user or API token that did it, or `null` from server code, and `site` the [site](/reference/multi-site) it happened on: `useAtelierEntries(site)` reads more of it. In a type that isn't [versioned](/reference/content-api#drafts-and-publishing), every save is published, but only the create and update hooks run.

## Before-hooks

A before-hook can change `data` in place: what it leaves there is validated and saved. It can stop the operation by throwing: nothing is written, and the caller gets the error. Throw `apiError(status, message, details)` from `#atelier/server` to choose what an API client sees; any other error answers `500` without its message.

`afterRead` can change the entries it gets in place: add a computed value, or remove one. It runs for drafts too (`stage`).

## After-hooks

After-hooks run once the change is committed. A failing after-hook doesn't undo it: the error is logged, and recorded in the [audit log](/reference/authentication#the-audit-log) as `hook.failed`, with the hook and the error, for the admin to show.

Changes made as a side effect don't run hooks: the other side of a [two-way relation](/reference/fields#relations), or a reference cleared because the entry it pointed to was deleted. For work that can fail and should be retried, queue a [background job](/reference/jobs) from the after-hook rather than doing it there.
