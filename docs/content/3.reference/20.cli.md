title: CLI
description: The atelier command: setup, migrations, users, content export and import, and background jobs.
---

The `atelier` command comes with `nuxt-atelier`. Run it in your app's directory, or point it at one with `--root <dir>`. It reads the database URL from `NUXT_ATELIER_DATABASE_URL` or `atelier.database.url` in `nuxt.config.ts`.

```bash
npx atelier <command> [options]
```

## Setup

| Command | Does |
|---|---|
| `atelier init` | adds `NUXT_APP_SECRET` and `NUXT_ATELIER_JOBS_SECRET`, with new random values, to `.env`, and a first collection (`server/atelier/collections/pages.ts`) when there are none. Never overwrites: run it again safely |

## Migrations

| Command | Does |
|---|---|
| `atelier migrate generate` | writes a migration for schema changes (`--name`, `--drop`, `--rename`, `--dialect`) |
| `atelier migrate apply` | applies pending migrations |
| `atelier migrate status` | lists applied and pending migrations |

See [Migrations](/reference/migrations) for how they work.

## Users

For when nobody can sign in: a lost administrator password, or a first administrator on a server without the setup screen. They work with the built-in [authentication](/reference/authentication), on the database directly.

| Command | Does |
|---|---|
| `atelier user create-admin --email <email> [--name <name>]` | creates an administrator |
| `atelier user reset-password --email <email>` | sets a new password and signs the user out of every session, a stolen one included |

Both generate a password and print it once. To choose it, pipe it in with `--password-stdin`, so it doesn't end up in your shell history:

```bash
printf '%s' "$NEW_PASSWORD" | npx atelier user reset-password --email ada@example.com --password-stdin
```

Both are recorded in the [audit log](/reference/authentication#the-audit-log), with no actor and `by: 'cli'`.

## Content

| Command | Does |
|---|---|
| `atelier export <file>` | writes all content to a portable archive, gzipped when `<file>` ends in `.gz` |
| `atelier import <file>` | loads an archive into an empty, migrated database, on any engine |

See [Backup and moving databases](/deployment/backup).

## Background jobs

| Command | Does |
|---|---|
| `atelier jobs list [--status failed]` | jobs, newest first, with their last error; `--status` is `queued`, `running` or `failed` |
| `atelier jobs retry <id>` | queues a failed job again |
| `atelier jobs run --url <site>` | runs due jobs now, on the running site |

`jobs run` asks the site: job handlers live in your app's server, not in the command. It calls the [trigger endpoint](/reference/jobs#the-trigger-endpoint) with `NUXT_ATELIER_JOBS_SECRET`, and `--url` defaults to `NUXT_PUBLIC_ATELIER_SITE_URL`.

Every command exits with `1` and a message on failure; set `ATELIER_DEBUG=1` for the full error.
