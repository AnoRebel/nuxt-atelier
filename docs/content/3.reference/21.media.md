The media library keeps your site's images, videos, audio and documents. Files go to a storage driver; their details (alt text, tags, folder…) go to the database.

## Uploading

Send the file itself as the request body, with its name in the query:

```ts
await $fetch('/api/_atelier/media', {
  method: 'POST',
  query: { filename: file.name, folder: 'team', private: 'false' },
  body: file, // a File or Blob: streamed, never held in memory whole
})
```

```json
{ "id": "6d0e…", "filename": "ada.jpg", "mime": "image/jpeg", "size": 184211, "folder": "team", "tags": [], "private": false, "url": "/_atelier/media/6d0e…/ada.jpg", … }
```

Uploading needs the `media` [capability](/reference/permissions#a-role) (editors have it), and counts toward `limits.writesPerMinute`.

- **The type comes from the file's content**, never from its name or the request: an executable renamed `photo.jpg` is refused (`415`, `unsupported_type`). [`media.accept`](/reference/configuration#media) lists the types allowed: images, video, audio and PDF by default. Formats only recognisable by their name, like SVG and plain text, can't be checked, so they can't be allowed.
- **Size:** at most [`limits.maxUploadSize`](/reference/configuration#limits) (50 MB by default); a larger file is refused (`413`, `too_large`) and nothing of it is kept.

### Large files and unreliable connections

For big files, upload in chunks that survive a dropped connection:

```ts
const { id } = await $fetch('/api/_atelier/media/uploads', { method: 'POST', body: { filename: file.name, size: file.size } })
let offset = 0
while (offset < file.size) {
  const chunk = file.slice(offset, offset + 8 * 1024 * 1024)
  try {
    offset = (await $fetch(`/api/_atelier/media/uploads/${id}`, { method: 'PUT', query: { offset }, body: chunk })).received
  }
  catch (error) {
    // 409: the server says where it stands (`data.received`); a dropped connection: ask, then resume
    offset = error.data?.data?.received ?? (await $fetch(`/api/_atelier/media/uploads/${id}`)).received
  }
}
const item = await $fetch(`/api/_atelier/media/uploads/${id}/complete`, { method: 'POST' })
```

Each chunk must start where the upload stands, `received`: a chunk at another offset, or one sent twice, is refused with `409` and `received`, so the client continues from there. Nothing of a chunk whose connection dropped is kept. Completing checks the file's type and size like any upload, and the finished file is identical to the original. The whole file is still limited to `limits.maxUploadSize`. `DELETE /api/_atelier/media/uploads/<id>` abandons an upload; ones left for a day are cleaned up by a [background job](/reference/jobs). An upload in progress belongs to whoever started it.

## Details

| Field | What it holds |
|---|---|
| `title`, `caption`, `credits` | text |
| `alt` | alt text per locale: `{ "en": "…", "et": "…" }`, or `""` for one shared by every locale |
| `folder` | where it's filed, like `team/2026`; `""` is the top level |
| `tags` | words to find it by |
| `focal` | where the subject is, `{ x, y }` from 0 to 1, for crops |
| `private` | see [Private files](#private-files) |

`PATCH /api/_atelier/media/<id>` changes them. `mime`, `size`, `filename` and the dates are set by the upload.

## Finding media

`GET /api/_atelier/media` lists it, newest first, with the [query language](/reference/querying) on `filename`, `title`, `caption`, `credits`, `folder`, `tags`, `mime`, `size` and `private`:

```http
GET /api/_atelier/media?filter={"tags":{"contains":"team"}}
GET /api/_atelier/media?filter={"folder":{"eq":"team"},"mime":{"contains":"image/"}}&sort=filename
```

Any signed-in user can browse the library, to pick files for their content.

## Serving

Files are served at their `url`, `/_atelier/media/<id>/<filename>`. A file's URL never changes (a new file gets a new id), so it's cached for a year (`Cache-Control: public, max-age=31536000, immutable`).

### Image variants

With [`sharp`](https://sharp.pixelplumbing.com) installed (`npm i sharp`), an image's URL also serves resized, cropped and converted versions:

```
/_atelier/media/6d0e…/ada.jpg?w=640                 640 px wide
/_atelier/media/6d0e…/ada.jpg?w=640&ar=1:1           a square, cropped around the focal point
/_atelier/media/6d0e…/ada.jpg?w=1280&format=avif     AVIF
```

- `w` is one of [`media.widths`](/reference/configuration#media) (320, 640, 960, 1280, 1920 and 2560 by default); others are refused, so nobody can fill your storage with sizes. An image is never enlarged.
- `ar` crops to `1:1`, `4:3`, `3:4`, `3:2`, `2:3`, `16:9`, `9:16` or `21:9`, keeping the item's `focal` point in view (the centre without one).
- `format` is `webp`, `avif`, `jpeg` or `png`; the original's otherwise.

Each variant is made on its first request and kept next to the original in storage, then cached like the original. Deleting the item deletes its variants. Uploads record an image's `width` and `height`, for markup that doesn't shift as it loads.

Without `sharp`, on Cloudflare Workers for example, variant URLs serve the original, and images have no recorded size.

## Where it's used, and deleting

Every save records the media an entry uses: in media fields, in objects and repeaters, and in blocks, nested ones included. `GET /api/_atelier/media/<id>/usage` lists those places, in drafts and in what the site serves:

```json
[{ "type": "pages", "id": "8f1c…", "field": "content.2.props.image" }, { "type": "posts", "id": "41aa…", "field": "cover" }]
```

Deleting an item that's in use is refused with `409` (`referenced`), listing them in `usages`, so the admin can show what would lose it. `DELETE /api/_atelier/media/<id>?force=true` deletes it anyway; those entries then point to nothing. Deleting removes the file too.

### Private files

A file marked `private` is served only to signed-in users, with `Cache-Control: private, no-store`. Anyone else gets a `404`, as if it didn't exist. Don't link to private files from public pages.

## Storage

`storage.driver` says where files go. Whichever you choose, files are served by your app at the same URLs.

### Local disk (the default)

Files go to [`storage.dir`](/reference/configuration#storage) on the server (`.data/uploads` by default, `NUXT_ATELIER_STORAGE_DIR` at runtime), and nothing is linked into `public/`. Keep that directory on a persistent volume, and back it up with your database. Building for a host whose disk doesn't last (Vercel, Netlify, Cloudflare and other serverless or edge platforms) prints a warning: uploads made there would be lost.

### S3-compatible storage and Cloudflare R2

```bash
npm i @nuxt-atelier/storage-s3
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-atelier', '@nuxt-atelier/storage-s3'],
  atelier: { storage: { driver: 's3' } },
})
```

```bash [.env]
NUXT_ATELIER_S3_ENDPOINT=https://<account id>.r2.cloudflarestorage.com   # or https://s3.<region>.amazonaws.com, a MinIO URL…
NUXT_ATELIER_S3_BUCKET=media
NUXT_ATELIER_S3_REGION=auto                                              # your bucket's region on AWS
NUXT_ATELIER_S3_ACCESS_KEY_ID=…
NUXT_ATELIER_S3_SECRET_ACCESS_KEY=…
```

The bucket can stay private: your app reads files with the keys and serves them. Requests are signed with [aws4fetch](https://github.com/mhart/aws4fetch), which works on edge runtimes too. Large files are uploaded in 5 MB parts, so memory stays low whatever their size, and a failed upload leaves no parts behind.

### Vercel Blob

```bash
npm i @nuxt-atelier/storage-vercel-blob
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-atelier', '@nuxt-atelier/storage-vercel-blob'],
  atelier: { storage: { driver: 'vercel-blob' } },
})
```

Connect a Blob store to your Vercel project; it sets `BLOB_READ_WRITE_TOKEN`, which the driver uses (or set `NUXT_ATELIER_VERCEL_BLOB_TOKEN`). Files are stored private, so they're only reachable through your app, private media included.

### Your own driver

A driver implements `put`, `get`, `head` and `delete` on Web Streams (`StorageDriver` from `nuxt-atelier/storage`), and is registered from a server plugin:

```ts [server/plugins/storage.ts]
import { registerStorageDriver } from '#atelier/server'

export default () => {
  registerStorageDriver(() => createMyDriver())
}
```
