title: Fields

Fields are created with helper functions from `#atelier/server` (or `#atelier` in app code):

```ts
import { number, text } from '#atelier/server'

const fields = {
  title: text({ required: true }),
  price: number({ min: 0 }),
}
```

## Options every field takes

| Option | What it does |
|---|---|
| `label` | the input's label in the admin |
| `help` | help text shown under the input |
| `required` | must have a value (see [Validation](/reference/validation)) |
| `unique` | no two entries may share the value (top-level fields only) |
| `default` | the initial value for new entries and blocks |
| `validate` | extra validation with any [Standard Schema](https://standardschema.dev) |
| `renamedFrom` | the field's previous key, after a rename: its data moves instead of being dropped (top-level fields only, see [Renaming](/reference/content-schema#renaming)) |
| `when` | the field applies only while a condition on another field holds (see [Conditional fields](#conditional-fields)) |
| `shared` | in a [localized](/reference/localization) type: one value for every locale, not translated (top-level fields only) |

Defaults are copied for each new entry or block, so an array or object default is never shared between them.

## Conditional fields

A field with `when` applies only while a condition on another field's value holds. While it doesn't, the field is hidden in the admin, isn't required, and isn't stored: a value left from before is dropped on save.

```ts
fields: {
  linkType: select({ options: ['internal', 'external'], required: true }),
  page: relation({ to: 'pages', required: true, when: { field: 'linkType', eq: 'internal' } }),
  url: url({ required: true, when: { field: 'linkType', eq: 'external' } }),
}
```

Saving with `linkType: 'internal'` and no `url` succeeds; with `linkType: 'external'` and no `url`, it's refused with `required` on `url`.

| Condition | Holds when the other field's value… |
|---|---|
| `{ field, eq: value }` | equals `value` |
| `{ field, ne: value }` | doesn't equal `value` |
| `{ field, in: [a, b] }` | is one of them |
| `{ field, set: true }` | isn't empty (`set: false`: is empty) |

`field` names a sibling: a field in the same object or repeater item. A leading `/` names a top-level field instead, from anywhere: `{ field: '/kind', eq: 'event' }`. A condition naming a field that doesn't exist stops the schema from loading.

## Field types

| Helper | Stores | Options |
|---|---|---|
| `text()` | a string | `minLength`, `maxLength`, `pattern`, `patternMessage` |
| `textarea()` | a multi-line string | `rows`, `minLength`, `maxLength` |
| `richText()` | a rich text document (ProseMirror JSON, never HTML) | |
| `number()` | a number | `integer`, `min`, `max` |
| `boolean()` | `true` or `false` | |
| `select()` | one of the `options` | `options` (required) |
| `multiSelect()` | a list of distinct `options` | `options` (required), `minItems`, `maxItems` |
| `date()` | a date string | `mode`: `'date'` (`2026-11-03`), `'datetime'` (`2026-11-03T09:30:00Z`, always UTC), `'time'` (`09:30`) |
| `email()` | an email address | `minLength`, `maxLength` |
| `url()` | an `http://` or `https://` URL | `minLength`, `maxLength` |
| `slug()` | a slug like `my-page` | `from` (the field to derive it from), `minLength`, `maxLength` |
| `color()` | a hex color like `#ff8800` | `alpha` (also accepts `#ff880080`) |
| `json()` | any JSON value | |
| `media()` | a media item's id | `accept` (MIME patterns like `image/*`) |
| `relation()` | an entry's id, or a list of ids with `many` | `to` (the collection, required), `many`, `onDelete`, `minItems`, `maxItems` |
| `object()` | a group of nested fields | `fields` (required) |
| `repeater()` | a list of items with nested fields | `fields` (required), `minItems`, `maxItems` |
| `blocks()` | a list of [blocks](/reference/blocks) | `allow` (block names; all when omitted), `minItems`, `maxItems` |

`url()` accepts only `http(s)` URLs, so a stored value can't become a `javascript:` link.

### Options for `select` and `multiSelect`

Options are plain values, or `{ value, label }` when the admin should show a different label:

```ts
select({ options: ['draft', { value: 'published', label: 'Published' }] })
```

### Nested fields

`object` and `repeater` take their own `fields`, which can nest further:

```ts
repeater({
  fields: {
    question: text({ required: true }),
    answer: richText(),
    meta: object({ fields: { order: number({ integer: true }) } }),
  },
})
```

## Relations

A relation stores the id of an entry in the `to` collection, or a list of ids with `many: true`. It works at any depth, inside objects and repeaters too.

```ts
author: relation({ to: 'authors' }),
tags: relation({ to: 'tags', many: true, onDelete: 'nullify' }),
article: relation({ to: 'articles', onDelete: 'cascade' }), // in comments.ts
```

### When the referenced entry is deleted

`onDelete` decides what deleting a referenced entry does to the entry holding the reference:

| `onDelete` | Deleting the referenced entry |
|---|---|
| `'restrict'` (default) | is refused with a `409` that lists every entry still referencing it |
| `'nullify'` | removes the reference: a single relation becomes `null`, a list loses the id. The holding entry gets a new version |
| `'cascade'` | deletes the holding entry too, applying its own relations' rules in turn |

A delete applies all of it at once, or nothing: if a cascade reaches an entry that a `restrict` relation still points to, the whole delete is refused. A singleton can't be deleted, so its relations can't `cascade`.

`nullify` doesn't validate the entry it changes: removing the only value of a `required` relation leaves an entry that must be fixed on its next save.

### Two-way relations

Give two relations each other's name as `inverse` to keep them in sync. A book's writers then list the book, and a writer's books list the writer, whichever side an editor changes:

```ts
// books.ts
writers: relation({ to: 'writers', many: true, inverse: 'books' }),
// writers.ts
books: relation({ to: 'books', many: true, inverse: 'writers' }),
```

- **Saving one side updates the other** in the same transaction. Each entry on the other side that gains or loses a link gets a new version, so an editor with a stale copy of it gets a `409` when saving.
- **A side that holds one entry moves the link.** If `chapters.book` is the inverse of `books.chapters`, adding a chapter to book B2 sets its `book` to B2 and takes it out of the chapters of its old book.
- **The two sides can be the same field.** `friends: relation({ to: 'people', many: true, inverse: 'friends' })` makes friendship mutual.
- **Deleting an entry unlinks it from the other side.** Its inverse defaults to `onDelete: 'nullify'` instead of `'restrict'`; set `onDelete` to change that.
- **Permissions cover both sides.** Through the API, a change that would update entries on the other side needs permission to update those entries and to write their inverse field. Otherwise it's refused with a `403`.
- **Only top-level relations of collections** can have an inverse, and both fields must name each other. This is checked when the schema loads.

Like `nullify`, the other side isn't validated: if it's `required` and loses its only value, or a `maxItems` is exceeded, that entry must be fixed on its next save.

### Reading related entries

Relations read as ids. Pass `depth` to get the entries instead:

```ts
const entries = await useAtelierEntries()
const article = await entries.get('articles', id, { depth: 1 })
article.data.author // { id, version, createdAt, updatedAt, data: { name: 'Ada', … } }
```

Each level of depth follows one more relation: with `depth: 2`, the author's own relations are entries too. A referenced entry that no longer exists reads as `null`, or is left out of a list.

## Custom field types

Define a field type once, then use it like a built-in one, in any collection, singleton, object or repeater:

```ts [server/atelier/fields/geo-point.ts]
import * as v from 'valibot'
import { defineFieldType } from '#atelier/server'

export const geoPoint = defineFieldType({
  name: 'geo-point',
  storage: 'json',
  schema: v.object({
    lat: v.pipe(v.number(), v.minValue(-90), v.maxValue(90)),
    lng: v.pipe(v.number(), v.minValue(-180), v.maxValue(180)),
  }),
  input: 'GeoPointInput',
})
```

```ts [server/atelier/collections/places.ts]
import { defineCollection, text } from '#atelier/server'
import { geoPoint } from '../fields/geo-point'

export default defineCollection({
  fields: {
    name: text({ required: true }),
    location: geoPoint({ required: true, label: 'Location' }),
  },
})
```

| Option | What it does |
|---|---|
| `name` | the type's name: lowercase letters, digits and `-` |
| `storage` | how the value is stored: `'text'`, `'number'`, `'boolean'` or `'json'` |
| `schema` | validates the value, with any [Standard Schema](https://standardschema.dev). Its output type is the field's TypeScript type |
| `input` | the admin input: the name of a global Vue component that edits the value |

The field takes every [common option](#options-every-field-takes). `unique` works when the storage isn't `'json'`. The value is first checked against its storage (a string, a finite number, a boolean, JSON), then against `schema`; its errors are reported under the field's path, like any other field's.
