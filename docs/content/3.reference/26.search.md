Site search finds published content visitors may read. It runs on your database's own full-text search (SQLite and D1: FTS5; PostgreSQL: `tsvector`; MySQL and MariaDB: `FULLTEXT`), so there's no search service to run. The index is a table that `atelier migrate generate` adds to your migrations once.

## Choose what's searched

Mark fields `searchable`, with a weight: `3` counts most, `1` (or `true`) least. Matches in heavier fields rank first.

```ts [server/atelier/collections/posts.ts]
export default defineCollection({
  route: { pattern: '/blog/{slug}' },
  fields: {
    title: text({ required: true, searchable: 3 }),
    slug: slug({ required: true }),
    excerpt: textarea({ searchable: 2 }),
    body: richText({ searchable: true }),
    // all the text inside the blocks: their text, rich text and nested blocks
    content: blocks({ searchable: true }),
  },
})
```

Only types that visitors (the `public` role) may read are indexed, without the fields hidden from them. A type without searchable fields isn't searched.

## Keeping it fresh

Publishing indexes an entry; unpublishing and deleting remove it, at once. Drafts are never in the index. After adding `searchable` to fields of existing content, or after a restore, rebuild the index:

```bash
npx atelier search rebuild   # on the running site: needs NUXT_ATELIER_JOBS_SECRET, and --url or NUXT_PUBLIC_ATELIER_SITE_URL
```

Administrators can rebuild it with `POST /api/_atelier/search/rebuild` too.

## Searching

```vue [app/pages/search.vue]
<script setup lang="ts">
const q = ref('')
const { data } = useAtelierSiteSearch(q, { limit: 10 })
</script>

<template>
  <input v-model="q" type="search" aria-label="Search">
  <ul>
    <li v-for="item in data.items" :key="`${item.type}:${item.id}`">
      <NuxtLink v-if="item.path" :to="item.path">{{ item.title }}</NuxtLink>
      <!-- matches in <mark>, everything else escaped -->
      <p v-html="item.excerpt" />
    </li>
  </ul>
</template>
```

The endpoint is `GET /api/_atelier/search?q=…&types=posts,pages&locale=de&limit=10&offset=0`, answering `{ items: [{ type, id, locale?, title, path, excerpt, score }], total, limit, offset }`. Every word must match; the last one also matches as the start of a word, so results appear while typing. A localized type answers the requested locale's versions.

The query is plain text: at most 200 characters and 10 words, letters and digits only. Quotes, operators and SQL are ignored, never interpreted. Each address may search 60 times a minute.

On MySQL and MariaDB, words shorter than three letters aren't indexed (InnoDB's `innodb_ft_min_token_size`), so they're left out of queries too.

## Searching in the admin

The admin has its own search (the magnifier in the top bar, or **Ctrl+K** / **⌘K**), separate from site search: it finds entries by title, drafts included, pages of settings, users (for those who manage them) and the admin's own screens, only where the signed-in user may read. Kits use `GET /api/_atelier/search/admin?q=…`, answering `{ results: [{ kind, type?, id, title, detail? }] }`, or `useAtelierGlobalSearch(query)`.

## Another search engine

To search with Meilisearch, Algolia, Typesense or another service, register an adapter in a server plugin. It gets the same documents (an entry's searchable text in three weights) and answers the same queries:

```ts [server/plugins/search.ts]
import { registerSearchAdapter } from '#atelier/server'

export default defineNitroPlugin(() => {
  registerSearchAdapter(() => ({
    name: 'meilisearch',
    async index({ type, id, locale, a, b, c }) { /* add or replace the document */ },
    async remove(type, id, locale) { /* remove an entry's documents */ },
    async clear(type) { /* remove every document, or a type's */ },
    async search({ terms, types, locale, limit, offset }) {
      return { hits: [/* { type, id, locale, score, excerpt } */], total: 0 }
    },
  }))
})
```
