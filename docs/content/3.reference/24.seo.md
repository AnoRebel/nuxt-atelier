title: SEO
description: Page titles, descriptions, sharing images and canonical URLs, rendered on the server.
---

Pages served by the CMS get their title, description, canonical link and Open Graph and Twitter tags in the HTML the server sends, so search engines and link previews see them without running JavaScript.

## Where the values come from

Add an `seo` field to a routable type to let editors set them:

```ts [server/atelier/collections/posts.ts]
export default defineCollection({
  route: { pattern: '/blog/{slug}' },
  fields: { title: text({ required: true }), slug: slug(), excerpt: textarea(), cover: media(), seo: seo() },
})
```

`seo()` holds a title, a description, a sharing image, a canonical URL, and "hide from search engines" (`noindex`) and "don't follow links" (`nofollow`) switches. Whatever is left empty falls back to the entry, then to the page:

| Tag | From |
|---|---|
| title | `seo.title`, else the entry's `title`, else its `name` |
| description | `seo.description`, else `description`, `excerpt` or `summary` |
| sharing image | `seo.image`, else `image` or `cover` (a media field) |
| canonical | `seo.canonical`, else the page's own URL |
| robots | `noindex` and `nofollow` when switched on |

Without an `seo` field, the fallbacks still apply.

## Site-wide settings

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  atelier: { seo: { titleTemplate: '%s · My site' } },
})
```

`%s` stands for the page's title. Set `NUXT_PUBLIC_ATELIER_SITE_URL` so canonical and image URLs are absolute, as search engines and social networks want.

Your own pages and components can set their own tags with Nuxt's `useSeoMeta`; theirs win over the CMS's.

## Translations

A [localized](/reference/localization) entry published in more than one locale links each translation with `<link rel="alternate" hreflang="…">`, at its URL as the site's i18n module prefixes it. The routes API returns these paths as `alternates`.

## Structured data

Give a type's pages [JSON-LD](https://schema.org) with `route.jsonLd`, a function of the entry that runs on the server for each page:

```ts [server/atelier/collections/posts.ts]
export default defineCollection({
  route: {
    pattern: '/blog/{slug}',
    jsonLd: ({ data, url, createdAt, updatedAt }) => ({
      '@type': 'Article',
      'headline': data.title,
      'url': url,
      'datePublished': createdAt,
      'dateModified': updatedAt,
      'author': { '@type': 'Person', 'name': 'Ada Lovelace' },
    }),
  },
  fields: { /* … */ },
})
```

`url` is the page's absolute URL when `NUXT_PUBLIC_ATELIER_SITE_URL` is set. Structured data for every page, like your organization, goes in `atelier.seo.jsonLd`. Both get `@context`, and are written so no value can break out of the script element.

## Sitemap

`/sitemap.xml` lists every published page of the CMS that visitors may read, with its last change and, for localized types, its translations as alternates. Pages whose `seo` field says `noindex`, drafts and unpublished entries aren't in it. Addresses are absolute against `NUXT_PUBLIC_ATELIER_SITE_URL`, else the address the sitemap was requested at.

With [`@nuxtjs/sitemap`](https://nuxtseo.com/docs/sitemap) installed (standalone or in `@nuxtjs/seo`), the CMS pages join its sitemap instead, as a source, and it serves `/sitemap.xml`. The same list is at `GET /api/_atelier/sitemap` as JSON (`[{ loc, lastmod, alternatives }]`) for any other tool.

## robots.txt

`/robots.txt` always keeps crawlers out of the admin and the CMS API. Add your own rules in `nuxt.config`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  atelier: {
    seo: {
      robots: {
        // false on a staging site: every crawler is asked to stay away from everything
        indexable: true,
        rules: [{ userAgent: ['GPTBot'], disallow: ['/'] }],
      },
    },
  },
})
```

Administrators (and roles that manage settings) change them in the admin, under **Search engines**: saved there, they override the configuration until **Use the configuration** brings it back. The settings API is `GET`, `PUT { value }` and `DELETE` on `/api/_atelier/settings/robots`.

With [`@nuxtjs/robots`](https://nuxtseo.com/docs/robots) installed, these rules are added to its own, and it serves `/robots.txt`. A `public/robots.txt` or `public/sitemap.xml` of your own is served instead of the CMS's.
