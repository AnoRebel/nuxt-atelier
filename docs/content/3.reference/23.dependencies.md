Each runtime dependency of a published package is listed here with what it's for. CI fails when one isn't (`bun run deps`), and when one is installed but unused (knip). Licenses are checked on every install (`bun run licenses`).

## Installed with nuxt-atelier

| Package | What it's for |
|---|---|
| `@nuxt/kit` | the Nuxt module API: adding pages, server handlers, templates and types |
| `valibot` | validating entries, module options and API requests, with the same schemas in the admin and on the server |
| `drizzle-orm` | SQL for SQLite, libSQL, D1, Postgres, MySQL and MariaDB from one query builder, always parameterized |
| `@libsql/client` | the SQLite and libSQL (Turso) driver, the default database |
| `jiti` | loading the app's TypeScript content definitions in the CLI, without building the app |
| `oxc-parser` | reading block components' `defineBlock()` at build time, to register them without running them |
| `magic-string` | removing block schemas from the components the browser loads, with source maps |
| `@vue/compiler-sfc` | reading `<script setup>` of block components at build time |
| `vue-router` | matching paths against the app's own pages, to tell which entries a page hides |
| `file-type` | recognizing an upload's type from its content, not its name |
| `@tanstack/vue-form` | the public form block's form state and validation (with the server's own rules) |
| `h3` | the admin's real-time connection: Nitro's WebSocket handler (`defineWebSocketHandler`), the h3 version Nitro 2 serves with |

## Installed by you, when you need them

| Package | What it's for |
|---|---|
| `nuxt` | the framework (4.6 or later) |
| `pg` | Postgres |
| `mysql2` | MySQL and MariaDB |
| `drizzle-kit` | generating migrations (`atelier migrate generate`), in development only |
| `@simplewebauthn/server` | passkey sign-in (`auth.passkeys`) |
| `sharp` | resizing and converting images; without it, originals are served or an image service makes the variants |
| `nodemailer` | sending email over SMTP (`NUXT_ATELIER_MAIL_URL=smtp://…`); the HTTP providers need nothing |
| `nuxt-atelier` | the core, for the adapter packages below |

## Installed with @nuxt-atelier/admin

| Package | What it's for |
|---|---|
| `@tanstack/vue-query` | the admin's server state: caching, refetching and mutations of CMS API data |
| `@tanstack/vue-form` | the admin's entry forms, validated with the same field rules as the server |
| `@iconify-json/lucide` | the Lucide icons the admin uses, bundled at build time (nothing is fetched from an icon service) |
| `@simplewebauthn/browser` | passkey sign-in in the admin; optional, and loaded only with `auth.passkeys` |
| `@tiptap/core`, `@tiptap/pm`, `@tiptap/vue-3`, `@tiptap/starter-kit` | the rich-text editor (Tiptap 3 on ProseMirror), loaded only when a rich-text field shows |

The admin's look comes from [crystal-neuo](https://github.com/AnoRebel/crystal-neuo), copied into the package (`scripts/sync-crystal-neuo.ts`), not installed.

## Installed with @nuxt-atelier/editor

| Package | What it's for |
|---|---|
| `@tiptap/core`, `@tiptap/pm`, `@tiptap/starter-kit` | rich text edited in place in the visual editor's preview, loaded by the page only in an edit session, on the first double click on a rich-text field |

Drag and drop, the command palette and the page bridge use the browser's own APIs: no other library.

## Installed with @nuxt-atelier/devtools

A development dependency: nothing of it reaches production.

| Package | What it's for |
|---|---|
| `@nuxt/kit` | registering the panels' dev server page |
| `h3` | the panels' page handler, on the dev server Nuxt runs |

The DevTools hooks it uses (`devtools:customTabs`, `devtools:ready`) are Nuxt's; `@nuxt/devtools-kit` is only a build-time dependency, for their types.

## Adapter packages

| Package | Depends on | What for |
|---|---|---|
| `@nuxt-atelier/auth-better-auth` | `better-auth` | signing in through Better Auth instead of the built-in adapter |
| `@nuxt-atelier/storage-s3` | `aws4fetch` | signing S3 requests (AWS, R2, MinIO…) with Web Crypto, without the AWS SDK |
| `@nuxt-atelier/storage-vercel-blob` | `@vercel/blob` | Vercel Blob storage |
| `@nuxt-atelier/ai` | `ai`, `zod` | AI assist on the AI SDK (any of its providers, installed by you); `zod` is the SDK's schema library |
| `@nuxt-atelier/i18n-micro`, `@nuxt-atelier/i18n-nuxtjs` | (`@nuxt/kit` only) | choosing the i18n module the site's URLs follow |
| `@nuxt-atelier/layer` | `nuxt-atelier`, `@nuxt-atelier/admin` | the module and the admin, which the layer installs, with an admin home to make your own |
