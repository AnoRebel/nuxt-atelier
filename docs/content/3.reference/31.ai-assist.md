---
title: AI assist
description: Optional AI suggestions for editors and an assistant, on any AI SDK provider, under your limits and exclusions.
---

AI assist is off unless you install `@nuxt-atelier/ai` and give it a provider. Then editors with the `ai` [capability](/reference/permissions#a-role) get suggestions they review before anything changes, and an assistant that proposes API requests for them to approve. Without it, the admin has no AI actions and its bundle no AI code.

## Turning it on

```bash
npm install @nuxt-atelier/ai @ai-sdk/anthropic   # or any AI SDK provider
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-atelier', '@nuxt-atelier/admin', '@nuxt-atelier/ai'],
  atelierAi: {
    exclude: ['customers', 'posts.internalNotes', 'media'],
    requestsPerHour: 60,
    tokensPerDay: 200000,
  },
})
```

```ts [server/plugins/ai.ts]
import { anthropic } from '@ai-sdk/anthropic'
import { aiSdkAdapter, registerAiAdapter } from '#atelier-ai'

export default defineNitroPlugin(() => {
  // the provider reads its key (ANTHROPIC_API_KEY) on the server; it never reaches the browser
  registerAiAdapter(() => aiSdkAdapter({ model: anthropic('claude-sonnet-5-5') }))
})
```

Any [AI SDK](https://ai-sdk.dev) model works, or your own adapter: an object with `generate({ system, prompt, images?, maxOutputTokens? })` answering `{ text, usage? }`. Then generate a migration: AI usage is recorded in its own table.

| Option | Default | |
|---|---|---|
| `exclude` | `[]` | content types (`customers`), fields (`posts.internalNotes`) and `media` whose content is never sent to the provider |
| `requestsPerHour` | `60` | AI requests per user per hour; then `429` |
| `tokensPerDay` | `200000` | tokens (in and out, as the provider reports them) per user per 24 hours; then `429` |

## What editors get

Every action asks the server, which asks the provider; the answer is a suggestion shown for the editor to edit, accept or discard. Accepting puts it in the form, unsaved, and **Undo** takes it back.

| Action | Where |
|---|---|
| **Rewrite**, **Shorten**, **Expand** | under text fields |
| **Translate to …** | under text fields of a localized type, one per other locale |
| **Suggest a title and description** | on an entry with a [`seo()`](/reference/fields) group, written from the saved entry |
| **Suggest alt text** | in the media library, from the image itself |
| The **assistant** | the command palette (**Ctrl+K**): type what you need, choose **Ask the assistant** |

The assistant answers with content API requests, each shown with what it does. Nothing is sent until the editor ticks the ones they want and sends them; then their own browser sends them with their own session, so the server answers exactly as if they'd made them: a writer can't delete someone else's entry through the assistant any more than without it. Proposals are limited to `/api/_atelier/{collections,singletons,media}`.

## Privacy

- Only the server talks to the provider; its credentials stay there.
- Excluded types and fields, and fields hidden from the user by their role, are never sent: for a title and description the server reads the entry itself and leaves them out; a request about an excluded field is refused (`403`) before the provider is called.
- The assistant is told which types and fields the user may see, not their content.
- Each request is recorded: who, which action and type, when, and the tokens the provider reported. **AI usage** in the admin (for those who manage users) shows them per user and action for a period.

## The API

| Request | |
|---|---|
| `GET /api/_atelier/ai` | `{ enabled: true }`, or `404` without a provider |
| `POST /api/_atelier/ai/suggest` | `{ action: 'rewrite' \| 'shorten' \| 'expand', type, field, text }`, `{ action: 'translate', type, field, value, to, from? }` (a JSON value keeps its structure, ids and links), `{ action: 'seo', type, id? }`, `{ action: 'alt', media }`; answers `{ suggestion }` |
| `POST /api/_atelier/ai/assistant` | `{ request }`: `{ proposals: [{ method, path, body?, summary }] }` |
| `GET /api/_atelier/ai/usage?from&to` | `[{ userId, name, action, requests, inputTokens, outputTokens }]` |
