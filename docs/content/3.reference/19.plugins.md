title: Building plugins
description: Package collections, field types, blocks, hooks and jobs for other Nuxt Atelier sites to install.

A plugin is a Nuxt layer or a Nuxt module. It can bring everything an app can define, and sites install it like any other.

| A plugin can add | How |
|---|---|
| collections, singletons, roles, tables | files in `server/atelier/` (see [Content schema](/reference/content-schema)) |
| field types | `defineFieldType()`, exported for schemas to use (see [Fields](/reference/fields#custom-field-types)) |
| blocks | components in `app/blocks/` (see [Blocks](/reference/blocks)) |
| lifecycle hooks | a server plugin with `useServerHooks()` (see [Lifecycle hooks](/reference/hooks)) |
| background jobs | a server plugin with `defineJob()` (see [Background jobs](/reference/jobs)) |

Admin pages, editor features and translations join this list with the admin, the visual editor and localization.

## As a layer

A layer is the simplest plugin: the same folders as an app.

```
my-cms-plugin/
  nuxt.config.ts
  server/atelier/collections/events.ts
  server/plugins/events.ts       ← hooks and jobs
  app/blocks/EventCard.vue
```

Sites add it with `extends: ['my-cms-plugin']`. The app's own files win over a layer's with the same name, so a site can replace one of your blocks or collections.

## As a module

A module can do more at build time, and takes options. Give Nuxt Atelier a directory laid out like a layer with the `atelier:dirs` hook:

```ts [module.ts]
import { addServerPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: { name: 'atelier-events' },
  setup(_, nuxt) {
    const { resolve } = createResolver(import.meta.url)
    nuxt.hook('atelier:dirs', (dirs) => {
      dirs.push(resolve('./content')) // content/server/atelier/…, content/app/blocks/…
    })
    addServerPlugin(resolve('./runtime/plugin')) // hooks and jobs
  },
})
```

Its definitions come after the app's and its layers', which win on a clash. `atelier migrate generate` reads them too, so the site's migrations include your collections' tables.

## Field types

Export field types for the schemas, yours and the site's, to use. The validator is any [Standard Schema](https://standardschema.dev): Valibot, Zod or ArkType, or your own:

```ts [fields.ts]
import { defineFieldType } from '#atelier/server'

export const geoPoint = defineFieldType({
  name: 'geo-point',
  storage: 'json',
  schema: {
    '~standard': {
      version: 1,
      vendor: 'atelier-events',
      validate: value => isPoint(value) ? { value } : { issues: [{ message: 'expected { lat, lng } in degrees' }] },
    },
  },
})
```

## Hooks and jobs

Register them in a server plugin. Prefix job names with your plugin's name, and check `type` in hooks, since they run for every collection:

```ts [runtime/plugin.ts]
import { defineJob, useAtelierJobs } from '#atelier/server'
import { useServerHooks } from 'nuxt/server'

export default () => {
  defineJob<{ id: string }>('events:remind', ({ id }) => sendReminder(id))
  useServerHooks().hook('atelier:afterCreate', async ({ type, id, entry }) => {
    if (type === 'events')
      await (await useAtelierJobs()).enqueue('events:remind', { id }, { key: `events:remind:${id}`, runAt: dayBefore(entry.data.startsOn) })
  })
}
```

The repository's `test/fixtures/plugin-events` is a complete example, installed by `test/fixtures/plugin-host`.
